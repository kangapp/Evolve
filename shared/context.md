# 按缺口梳理项目

新工作形成方案、开展调查，或续接后准备实施时，先恢复当前适用的正式规则、相关工作记录和少量经验，再读现场核对。说明本轮选择的深度、理由、范围、仍可能改变结论的未知及停止条件；使用已取得的信息，不让用户机械填写深度选项。

- **轻量**：目标和局部约束已有可信依据，读取直接相关文件、原检查及与保存结果的差异。能说明目标行为、修改点、影响和验证方式时停止。复杂任务的后续小段也可以只做轻量核对。
- **定向深入**：相关资料缺失、跨模块链路不清，或症状与现有口径冲突时，沿调用、数据来源和消费关系追踪到能解释该问题的边界。列出实际覆盖的入口、关键转换、约束与未覆盖分支；决定实施或结论强度的未知得到核实后停止。局部问题也可能需要这一深度。
- **全局**：用户要求梳理整体项目，或尚无可信的整体结构、关键约束和模块职责时，核对入口、目录职责、主要业务或数据链路、检查与运行配置、已有规范和当前工作。形成带来源的整体结构与缺口后停止；只展开会影响当前目标的细节。

深度与简单／复杂任务分别判断，依据实际资料和缺口，不按代码行数或 init profile 决定。复用已有背景前核对来源、适用版本及当前相关字节；相关变化只扩大相应范围。新观察区分事实、推断和未知，未读当前外部数据时注明时效限制。

实施前须能说明目标行为、业务约束、主要修改点和影响、验证方式，以及仍可能改变方案的未知；调查须能说明问题、观察范围、来源、结论强度和未覆盖部分。遇到会改变目标或带来重大选择的缺口，说明具体影响并核对；其余独立工作沿有效授权推进。

梳理本身不授予修改或正式知识批准。只读解释直接报告观察；留档调查沿 analyze，工作方案沿 propose／update，续接沿原工作项；正式知识仍作为具体待审候选交对应 owner，不另建梳理状态或全局“已就绪”标记。
