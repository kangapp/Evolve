# 知识文档内容与图文约定

撰写、迁入、修订或验收正式文档时读取本页。执行字段见[项目知识交付](project-knowledge.md)，候选及实际验收见[正式知识协议](knowledge-candidates.md)。

## 选择职责与模板

调用只读 init.templates 查看 kind、默认位置与章节；init.templates 的位置参数给 kind 时，返回对应完整模板。未接入也可读取，不创建项目设施。包内模板位于 assets/templates/knowledge-<kind>.md。

| 类型 | 职责 | 基本阅读顺序 |
|---|---|---|
| project | 概况与知识导航 | 定位、目标边界、能力、导航、覆盖缺口 |
| codemap | 实现定位和协作 | 范围、入口、模块职责、关键链路、数据依赖、检查修改入口、未覆盖范围 |
| domain | 统一业务语言 | 范围、短定义与歧义词、概念关系、相关规格 |
| spec | 行为与验收 | 边界、前置、规则、异常、验收、依据与未决问题 |
| decision | 真实重要取舍 | 背景、决定、理由和影响，按需展开备选及替代关系 |
| development | 可执行开发步骤 | 前置、准备启动、检查及预期结果、问题与限制 |
| architecture | 系统级关系 | 边界、组件职责、交互依赖、约束与 ADR |
| data | 数据关系和口径 | 来源、标识粒度、关系转换、时间单位、质量限制 |
| rule | 正式项目约束 | 适用范围、规则、依据和例外 |

模板标题可以映射为同等职责的项目用语；必要信息完整，适用但未知的内容说明问题及影响，不填空壳。已有可靠文档初次映射保留原格式。短 ADR 可简洁表达背景、决定与理由，无需铺陈普通可逆选择。

已有资料按实际可靠主题和范围映射。若它只负责局部约定，内容判据检查该局部约定、来源、定位和缺口，调查记录说明尚未建立的完整规格；不能以整类模板的全部职责要求改写原文，也不能把局部资料称作完整规格。

## 写作

- 中文、统一业务术语、直接表达；路径与符号保留真实名称。
- 项目文件路径使用行内代码或有效 Markdown 链接；链接显示文字本身是路径时也用行内代码。修订时保持该格式，使路径定位和受限事实差异可以准确核对。
- 一段解释一个问题，结论后给依据、例子或必要边界。
- project 保持概述并链接细节；codemap 指向实际入口、符号和检查；domain 定义概念，具体行为约束链接 spec。
- spec 写明条件、行为、结果和可判别的异常，重要需求及 AC 使用稳定编号；预期来自独立约定，不从实现计算。
- ADR 保存当时真实取舍、代价和后继关系；缺失历史原因时保留未知。
- 指南按操作顺序给前置、动作、预期结果及失败处理。发现命令不等于已执行。
- 当前事实、推断、未知与未来目标分别标注；标明范围和来源，文件更新时间不代替观察时间。
- 候选 content 是准备应用后的正式正文。候选身份、批准、检查及图形渲染状态存入 presentation、观察和历史记录；正文描述项目知识及其观察限制，避免写入会因本次应用自动过时的流程状态。

## 图文

优先随正文维护 Mermaid。项目概况使用系统上下文图；代码地图使用模块关系与关键时序；领域使用概念关系；规格按需使用状态／流程／时序；数据使用 ER／数据流；ADR 在结构差异影响取舍时配图。

图前说明问题，图后解释边界与来源。图中用词与正文相同，箭头意义明确，推断和未来方案有标识；关键规则在正文也能读到。复杂关系拆为总览与局部图，简单内容无需配图。确需界面图片时保存可维护来源和适用版本，用有效相对路径引用。

Mermaid 候选额外声明 diagrams 内容判据：实际渲染是否成功、图文及来源是否一致。运行时检查围栏、声明和本地资源，实际渲染由宿主可用工具观察并保留依据；缺渲染能力时如实 blocked，源形状检查不能代称渲染通过。图片和图源变化时复核对应关系。

## 增量维护和检查

修改所属章节并保持完整当前正文；沿原风格更新受影响部分。主题有独立职责时拆分，知识细节确定一处权威、其他位置链接。版本过程保留在历史，避免正文不断追加本次更新流水。

候选 acceptance 至少含四个独立维度，key 固定为 structure、sources、consistency、usefulness；每项 text 给针对本正文的具体判据，可再增加业务内容条件。不要把“标题存在”当成整体质量。

- structure：职责和必要内容完整，路径／锚点／编号／资源有效，模板占位已替换。
- sources：结论有实际依据，范围及时点明确，未查部分保留限制。
- consistency：图文、术语、当前规格和实际成果一致；冲突和未来目标被明确表达。
- usefulness：读者能完成本类型的实际目的，例如找到实现、判断行为、执行操作或理解取舍。

sync.check 对批次中的候选可以解析同批目标引用；verify.knowledge 在实际文件应用后再次核对。先应用批次所需目标，再做最终文档验收。候选批准或渲染成功均不能代替实际文档与业务验收。

模板随包版本维护，升级不自动重排已有文档。需要格式迁入或结构变化时明确范围、来源和具体差异。

## 工作摘要和更新触发

工作摘要、复杂规格、任务和验收页由历史派生；查询不重建，编辑不改变事实。summary 按目标范围、方案、AC、任务检查、知识变化、当次结果和来源排列；spec 写问题、目标边界、行为约束、取舍、检查决定和真实未决项；tasks 给实际依赖及输入；verification 区分检查、AC覆盖和审查模式。原始回执及辅助副本保存在本地 review，正式知识保持登记位置。

codemap 在入口、职责、依赖方向或检查入口变化时复核；模块表给职责和真实路径，目录树之外说明关键链路。domain／rule／data 随概念、约束、口径、单位和时间语义变化复核。decision 记录真实问题、备选、采用理由、代价、状态和替代关系；缺少历史依据保留未知。development 随工具、环境及步骤变化复核，spec 随验收行为变化复核。

表格用于职责、映射和对比；图用于确实有助于理解的依赖、状态和数据流。派生任务图从同一依赖定义生成，正式图的实际渲染与图文一致性仍按本页验收。升级模板不重排已批准的旧正文。
