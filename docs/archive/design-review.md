## 1. 结论与方法

保留九个 Skill 加共享内核的架构。发现并修订下列 12 组契约问题，其中 P1 表示可能造成重复副作用、历史损失或错误放行，P2 表示会造成职责或使用语义不一致。它们是设计缺陷，修订不代表实现已经具备防护。

逐条核对命令负责者和副作用，再按初始化、修订、实施、验证、同步、归档、发布、晋升与恢复做场景走查。检查普通成功路径，也检查 prepare 后变更、响应丢失、源码已改未登记、数据库替换、外部未知和个人库提交后中断。

## 2. 已修订问题

### R-01 / P2：命令读写语义和默认动作不统一

原 contracts 将 release status 当作外部观察写入，workflow 与 Skill 目录却允许本地查询；experience review 的查看和审阅写入也未分清。doctor／next／经验工具接口覆盖不完整，recover 只暴露 OP。

修订：status 默认本地只读，--refresh 才外部查询并登记；review 默认只读、明确决定才写；补齐默认动作、promote 准备／应用和恢复目标。只读不能暗中索引、分配编号、更新 guard、标 stale 或备份。

契约：[命令映射及工具接口](../workflows.md#commands)、[工作流](../workflows.md#common)。验收：V-019、V-026、V-029。

### R-02 / P2：支持 Skill 和阶段 owner 有职责重叠

原方案既要求只由 owner 写阶段，又让各阶段直接提炼经验、自动备份；未说明是否新建 run，可能导致隐藏轮转或无限备份。

修订：业务 owner 固定；内部支持记录 component_skill、父 run 和 operation_id。独立 learn／backup 才创建新 run；晋升需具体确认；策略备份不递归触发自身备份。

契约：[Skill 边界](../workflows.md#commands)、[交接协议](../runtime.md#execution)、[备份协议](../runtime.md#recovery)。验收：V-027、V-035、V-039。

### R-03 / P1：多目标交接和业务有效性不足

单个 change_id／plan_revision／source_handoff 无法准确描述多变更发布；来源 row_version 增加还可能让先归档后发布误判失效。

修订：targets[]、source_handoff_ids[] 和逐对象 basis；区分来源快照版本、业务有效性和当前提交版本。归档移动与已验证规格同步有稳定身份及应用证明，不能以放宽 expected_version 来解决。

契约：[交接载荷及接收核查](../runtime.md#execution)、[存储](../runtime.md#data)。验收：V-021、V-022、V-030。

### R-04 / P1：阶段重试、终态和无 OP 中断未闭合

操作幂等不能防止 phase start／finish 重试生成多个 run／交接；无 OP 的 apply 中断无法使用旧 recover 入口；知识处理失败可能阻止记录真实业务结果。

修订：稳定 request_id、run 唯一请求键、source_run 唯一 handoff、提交时再次核查；run 终态不重开；recover --run 核对现场，不能补造测试。知识处理 pending／unavailable 与无新经验分开，不否认真实实现结果。

契约：[阶段生命周期](../runtime.md#execution)、[恢复目标](../runtime.md#recovery)。验收：V-023、V-031、V-032、V-039。

### R-05 / P1：restore 可能覆盖自身日志且无法恢复损坏库

原恢复意图只存于将被替换的数据库；损坏数据库又无法满足“先一致备份再恢复”。恢复旧 row_version 还可能接受旧写请求。

修订：独立换库 journal、保护副本、逐步核验及恢复后登记；损坏库使用已校验现场隔离分支。workspace_epoch 和检查点 guard 阻止旧请求重放；Git 历史切换显式核对，不自动合并；保护已知未决外部尝试，环境核清前阻止新的副作用尝试。跨机器首次接入仍不提供多机锁保证。

契约：[restore、损坏恢复与 guard](../runtime.md#recovery)、[控制数据](../runtime.md#data)。验收：V-033、V-034。

### R-06 / P1：外部尝试和发布投影可能错误放行

查询进程失败可能覆盖真实部署结果；回滚未区分原候选和恢复候选；短期文件锁无法阻止 unknown 尝试之后再次部署。个人库之外的外部事实也不会随 Git 或 restore 回退。

修订：attempt 执行结果和环境观察分开，保留最近确认事实及时间；回滚核对恢复候选；同环境未决尝试保留逻辑占用，先核实再释放；人工 record 如实记事实及规范缺口。

契约：[发布及未知结果](../runtime.md#recovery)。验收：V-009、V-015、V-036。

### R-07 / P1：验收门禁和归档终态可能遮盖范围缺口

局部验证通过、取消任务、组合多个旧候选的证据，都可能被误用为完整通过。归档终态又未明确允许后续发布所需的复验。

修订：逐项聚合当前有效 AC，旧通过不遮盖新失败；缩范围先修订并接受，取消任务不删除 AC。归档后可以追加冻结修订的复验，不能重写原任务；组合发布核查同一最终候选。启用发布后归档策略时明确所需环境。

契约：[验收与归档](../workflows.md#common)、[发布准备](../runtime.md#recovery)。验收：V-008、V-010、V-037。

### R-08 / P2：候选文档写入与提交边界不一致

原流程允许先覆盖当前规划文件，随后才检查版本／捕获旧值；这与“未确认不替代有效修订”冲突。prepare 与 start 之间也可能已有编辑。

修订：旧快照保留、候选暂存、校验与呈现、可恢复提升；直接编辑明确为 unregistered_changes。start 和每次实际提交重新核查，报告失败不重复业务动作。

契约：[多文件协议](../runtime.md#recovery)、[修订](../runtime.md#data)。验收：V-012、V-017、V-031。

### R-09 / P2：备份可能递归且截止点不清

若把整个资料目录打包，会递归包含 exports／旧恢复包／自身；备份无法包含未来才产生的自身 finish。普通写前和完成点备份失败的后果也未完全区分。

修订：权威集合与派生排除目录、证据迁入要求、producer 与截止点、进行中 run 清单；前置保护失败停止后续写入，后置失败独立报告，不回退已确认结果。

契约：[备份边界](../runtime.md#recovery)。验收：V-013、V-035。

### R-10 / P2：部分同步后修订可能重复应用增量

仅按增量修订防重不足以识别新 REV 中未改变的旧 ADD；已同步内容改变后的新基线也未明确。

修订：稳定 delta_id 加目标摘要，沿用已有应用事实；修改已同步行为以当前规格为基线产生后继增量及新验收，不重放旧 ADD。

契约：[同步](../workflows.md#common)、[增量与应用记录](../runtime.md#data)。验收：V-011、V-038。

### R-11 / P2：个人库晋升缺少跨库提交和路径例外

所有路径必须位于项目内与个人库写用户目录矛盾；项目提交前后个人库已写入的中断窗口可能导致重复晋升，项目 restore 也不能撤销个人库事实。

修订：仅对已确认 personal 目标开放受控路径；稳定 promotion_id、候选摘要、目标身份及两端提交；中断先查目标再补登记。确认／应用状态分开，恢复不自动撤回个人条目。

契约：[个人经验库协议](../workflows.md#learning)、[知识晋升](../workflows.md#learning)。验收：V-040。

### R-12 / P2：旧决策文案和实施依赖未统一

决策文件仍说具体拆分未确认，与 D-012 冲突；M1 已要求可靠初始化与规划，但可恢复写入、保护备份却全放 M3，阶段又在 M4 之前依赖尚不存在的学习能力。

修订：采用状态统一到 0.4.1；M1 前置最小维护、journal、操作恢复、guard 与备份基础，后续逐步扩展。学习能力未实现显式 unavailable。实施案例扩展至 V-040；本轮仍止于 M0。

契约：[决策](../delivery.md#decisions)、[实施与验收](../delivery.md#milestones)。验收：V-025、V-039 及里程碑检查。
