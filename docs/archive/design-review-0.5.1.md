# 0.5.1 完整设计审查：开发与独立分析双路径

> 历史审查快照：保留原版本结论；链接已迁往现行章节，仅作定位，不代表旧契约再次生效。逐字原文及当时图册见[重组前快照](pre-consolidation-0.5.2-20261028.zip)，当前规范见[文档入口](../README.md)。

审查日期：2026-10-27。对象为 0.5.1 设计；本轮直接修订后的基线为 **0.5.2**。保留九个 Skill、六个开发入口及一类 run，不开始插件编码。本文记录设计缺口及处置，不是运行时缺陷报告或功能测试通过证明。[0.4.1 审查](design-review.md)仍作为历史快照保留。

## 1. 结论与范围

0.5.1 的两条主路径成立，但在交界和异常分支存在八组不一致或未定义契约，已直接修订。主要风险是将记录接入误认为开发就绪、将已结束父阶段当成可追加工作、恢复时混淆分析与维护身份，以及把历史结论、方案接受和验收结果混为一谈。

本轮逐项走查入口／动作 owner、前置、允许副作用、Markdown 与 SQLite 权威、证据、结束结果、下一步、跨会话续接、中断恢复和转修复；对照 AGENT、架构、命令、Skill 目录、领域／存储、执行协议、恢复、经验、实施计划及两个模拟案例，并同步 SVG。

复核的代表路径：

1. 普通问答不留档 → 后来明确保存 → 最小记录接入。
2. 已有或未接入项目 → 独立分析 → 部分结论 → 只读恢复 → 新资料续查。
3. development init → propose → apply 内部排查 → verify → archive → 按需 release。
4. apply 已结束 → 新请求只排查 → 项目级 analyze 关联既有 CHG，不能重开旧实施。
5. 分析进行中退出 → maintain 恢复原 run → 新 analyze 顺序续查。
6. 旧来源已过时或被反驳 → 合法重检；证据／记录失败 → 如实限制结果；报告失败 → 重导。
7. 明确修复 → 新建或修订已有 CHG → 呈现有效 REV → 按原接受规则实施。
8. 分析发现候选经验 → 有来源与反例的建议 → 经具体确认的规则／个人库晋升。

## 2. 发现与修订

### R-01（高）：最小记录接入和完整初始化完成条件冲突

**原问题**：分析文档允许无骨架／规格接入，init／Skill 目录却统一要求骨架、行为基线和初始化任务；后续规划无法判断“已初始化”是否足够。

**修订**：init 输入 profile 分 records_only 与 development。前者仅配置、DB、最小范围导航及 init run；后者保留骨架／基线和 initialization 系统记录。实际覆盖和产物写入 run，开发就绪性按目标推导，后续补齐复用底座，不建第二套状态机。

**落点**：[工作流](../workflows.md#common)、[初始化与命令契约](../workflows.md#commands)、[存储](../runtime.md#data)、[Skill 目录](../workflows.md#commands)、AGENT；图 01／03／04。未来验收 V-054。

### R-02（高）：内部排查与独立分析缺少父阶段时态／副作用边界

**原问题**：“沿用父 run”未说明父阶段已经结束时怎样处理；只读业务与测试／辅助方法、正式知识修改之间存在隐含越界空间。

**修订**：仅仍 started 且获准的父阶段内排查复用父 run；新会话中的“只查”另建分析，可引用 CHG，不改任务／VER。当前限制约束后续操作，已发生事实不能抹除。隔离实验核对实际副作用，正式知识／配置修订及规则晋升走各自负责动作；来源建议不充当用户指令。

**落点**：[分析路径第 1—3 节](../workflows.md#analysis)、[统一执行协议](../runtime.md#execution)、[Skill 目录](../workflows.md#commands)、案例；图 16。未来验收 V-055。

### R-03（高）：分析定位、恢复身份和顺序续查缺少一致约束

**原问题**：标题“最近一次”和显式历史 RUN 语义不清；恢复后可能把 maintain 当 previous；不同请求可从同一历史头各自续查，形成隐式分叉。

**修订**：标题按链折叠主题，显式 RUN 保留快照并显示当前头。previous 仅接同项目 analyze，恢复后仍接原 interrupted 分析，维护仅作 source。start 事务核对所见头、无进行中后继及唯一后继，先查幂等；历史回看不抛弃新进展。无新分析实体、手工 head 或多机锁承诺。

**落点**：[分析续接](../workflows.md#analysis)、[phase_runs](../runtime.md#data)、[恢复](../runtime.md#recovery)、命令／协议；图 10／16。未来验收 V-056。

### R-04（高）：来源身份混用，过时结论可能阻碍合法重检或误作当前事实

**原问题**：source_runs 既表示 run 又允许直接 REV／VER；旧结论失效时，一律拒绝会妨碍重检，一律接受又会放松开发／发布依据。

**修订**：source_runs 只存执行引用；领域资料进入 typed references。purpose 区分 historical_context 与 decision_basis，required 决定是否阻止依赖动作；accepted 仅指适合该用途。过时／被反驳结论可用于重检，必需当前依据仍须有效。局部 F／H 由 run + digest + local_key 追溯，反驳追加事实并关联原条目，resume／当前依据核查展示后续纠正／取代提示，不改写过去。

**落点**：[输入核查协议](../runtime.md#execution)、[分析结果](../workflows.md#analysis)、[存储](../runtime.md#data)、[工具契约](../runtime.md#tools)；图 12／15／16。未来验收 V-057。

### R-05（高）：分析转修复一律新建，可能重复变更或绕过方案接受

**原问题**：原描述始终“新 CHG”，没有覆盖已存在修复变更、续查后修订方案及同一分析支持多个修复；分析完成也易被误认为可直接 apply。

**修订**：先定位已有明确匹配活动 CHG，按当前意图 create／update，歧义才问；不重开已归档／取消范围。分析通过 source_runs 作依据，不进修复续接链，不替代有效 REV 的呈现和接受，更不替代验收。已明确多阶段授权可继续，不重复确认；关键新选择先澄清。

**落点**：[转修复契约](../workflows.md#analysis)、[工作流](../workflows.md#common)、[使用指南](../workflows.md#common)、模拟案例；图 03／05／16。未来验收 V-058。

### R-06（中）：不留档和后来要求留档之间缺少时间及恢复语义

**原问题**：没有定义即时解释后补存、已存后要求不记录、进行中禁止继续写记录的处理，可能倒填执行或误删历史。

**修订**：补存建立当前 run，原解释作导入资料，重核或保留依据限制；不伪造过去执行。后续不记录不删除已有历史；明确停止写入时不偷偷 finish，说明未封存情况，后续明确恢复再维护。允许留档的主动结束由分析负责者封存实际范围与 user_stopped，不虚构业务 CHG cancel；已结束不建空 run。

**落点**：[留档意图变化](../workflows.md#analysis)、指南和案例。未来验收 V-059。

### R-07（高）：观察、持久化与证据完整性尚未清楚分离

**原问题**：已有认知结论不代表证据已完整保存；可空 VER 的证据来源校验、旧证据被采用时的观察者，以及外部引用恢复范围不充分。

**修订**：必需证据先持久化并核摘要，source_run 必填、VER 可空，保留原观察者和实际范围。记录失败如实报告未完整留档，外部引用说明可获取性及恢复限制。维护只补确定性事实，不能补造根因或测试；后续不单凭 answered 放行。

**落点**：[分析留档](../runtime.md#analysis-records)、[证据结构](../runtime.md#data)、[恢复](../runtime.md#recovery)、验收计划；图 11／16。未来验收 V-060。

### R-08（中）：旧报告重导与新分析、业务归档和知识晋升的边界不足

**原问题**：再次要求报告可能触发重复分析并改变主题最近结果；生成视图、报告失败以及分析 completed 的下一步缺少明确对应。

**修订**：原报告由 maintain export 从封存 run／digest 重导，不占分析链；VIEW_STALE 不回退或重查。禁止导出覆盖权威文件／证据。分析可留档结束，不必业务 archive，不直接推荐 apply；经验保留假设强度，正式规则／个人库走具体确认的 learn。

**落点**：[视图契约](../runtime.md#tools)、[分析路径](../workflows.md#analysis)、[推荐](../workflows.md#learning)、经验／实施计划；图 03／11／12／16。未来验收 V-061。

## 3. 修订后的承接原则

- **开发**：Markdown 定义当前／未来行为，SQLite 绑定有效修订、任务、实际验收及归档／发布事实；业务完成门禁保持原有强度。
- **独立分析**：run 记录认知目标、事实／假设／结论与限制，正式证据保存必要观察；analysis.md 只是生成视图，不修改业务规格。
- **跨会话**：同类顺序续接用 previous，跨阶段／恢复／复用来源用 source_runs；每次按用途重核。
- **转修复**：来源证据 → 定位 CHG → 形成并呈现有效 REV → 当前请求覆盖的实施／验证等阶段；认知结论、方案接受、实际验收、发布各自有依据。

这些属于现有对象和规则的收口，不引入额外用户命令、审批文件、分析对象或工作流阶段。用户仍可只发一个明确自然语言请求。

- 16 张 SVG 的 XML、标题／说明及 README 引用一致；浏览器渲染检查全部通过，文字无超出视口／标注框。
- README、审查、分析契约和排查案例渲染无失效图片或横向溢出；另人工查看初始化、跨会话恢复、独立分析三张关键图。
- 未创建 SKILL.md、history.db、插件源码或运行时；仅修改设计材料和文档图册源／生成产物。

以上检查仅证明本轮文档结构与表达，不能替代未来 V 系列功能验收。

个人跨会话按先后续接；本设计只检测库内顺序冲突及受控提交，不承诺合并并行调查、拦截全部外部编辑或跨多机协调。宿主入口／参数、SQLite 约束细节和证据写入故障注入仍需 M1—M4 实现验证。现有设计无需要用户补充信息才能完成本轮修订的阻塞项，且不以审查完成自动开始实现。
