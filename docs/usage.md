# 使用指南

Evolve 用项目记录连接方案、实施、检查和后续工作。你表达目标与允许的修改范围，AI 准备内部请求、定位工作项并推进流程。

不确定入口时说：“使用 Evolve，我想修改 X，帮我判断从哪里开始。”统一入口 evolve-workflow 可以解释用法、选择必要接入范围、恢复工作和分派阶段。只咨询保持只读；空项目先确认目标和最小验收行为。

## 1. 接入和理解项目

先按[安装指南](installation.md)在所用宿主启用插件，然后在目标项目说：

```text
使用 Evolve 接入这个项目，说明入口、主要模块和检查方式，暂不修改业务文件。
```

AI 根据资料缺口选择梳理范围：局部问题核对相关文件，链路不清时深入相关模块，需要整体理解时梳理全局。已有可信背景可以复用。

完整接入会调查目标、业务概念、行为、实现、数据契约、验证、决定和风险，深入主要业务链路与关键约束。AI 复用可靠文档，展示项目导航、代码地图等具体候选，按你的决定应用并验收，保存覆盖范围和缺口。大型项目可以分批完成。

只需要工具记录时可以说“仅接入记录设施，本轮不建立知识基线”；连接成功只代表配置和历史已建立。如果只是即时解释，可以说“只解释这个问题，暂不留档也不修改”，无需先接入或建立任务。

## 2. 提出工作目标

```text
总计结果似乎计算成了条数。先查明原因，展示简短方案；
在我确认的文件范围内修复，保留已有测试，完成检查、审查和验收后封存。
```

简单修改先说明目标、范围、完成条件和检查方式。复杂需求先形成完整方案及有依赖的任务清单。需要你确认的具体方案会呈现出来，已有授权在原范围内继续。

只讨论方案时可以说：“先保存这个功能的完整方案和任务清单，本轮不实施，等我确认。”

## 3. 实施、检查和完成

方案接受后，AI 按范围修改文件并执行约定检查。检查或审查发现必需问题时，在有效修改授权内修正并复测。测试与完成条件保留独立依据。

完成包括实际检查、逐项完成条件核对，以及规格和项目规范两方面的审查。最后封存成果并保存完成截点。单个命令成功或一个任务完成，不能代替整个目标完成。

也可以只要求检查：

```text
使用 Evolve 只验收这次修改，给出实际失败和必要改进，暂不修复源码或测试。
```

只验收保持文件和已完成任务的历史状态。若文件已被其他工具改动，新结果描述当前现场，旧通过记录仍保留为历史。

## 4. 暂停和换会话继续

中途结束时说：

```text
保存当前部分结果、未做事项和下一步，检查及验收下次继续。
```

正常暂停保存文件段和进度，不执行后检查，也不将任务记为完成。新会话说：

```text
使用 Evolve 继续“总计修复”任务，先核对当前代码和上次进度。
```

Evolve 从档案恢复原方案、授权范围、部分结果、失败和下一步，核对当前文件后继续。标题不唯一时明确选择。正常暂停与异常中断不同，中断处理见[排错指南](troubleshooting.md)。

## 常见请求

| 场景 | 示例 |
|---|---|
| 独立调查 | “只调查金额异常并保存结论与下一步，不创建修复任务。” |
| 复杂功能 | “为报告功能形成方案和依赖任务，确认后逐项实施，最后检查集成结果。” |
| 需求变更 | “增加可选均值输出，保留原默认行为，说明影响并修订方案。” |
| SQL 开发 | “只修改这份 SQL，按指定日期、去重和退款口径对账。” |
| 血缘整理 | “保存已调查的数据关系与来源，再从底稿导出 Markdown 报告。” |
| 项目文档 | “提出术语定义的具体修改，展示全文差异，确认后应用并检查。” |
| 经验复用 | “查一下上次同类问题的经验，按当前代码判断是否适用。” |
| 取消工作 | “取消这项工作，保留已有文件和完成记录。” |

复杂任务、知识协作和数据操作见[工作流指南](workflows.md)。

## 工作资料保存在哪里

| 位置 | 内容 |
|---|---|
| `evolve/config.toml` | 项目身份、历史路径和已登记的检查命令 |
| `evolve/history.db` | 方案、任务、调查、检查、知识版本及工作历史 |
| `.evolve-local/` | 本机日志、保护索引、备份和执行协调信息 |
| `.evolve-local/exports/` | 从调查底稿导出的报告 |
| 具体映射的文档路径 | 经过明确批准的项目说明、术语或规则正文 |

插件安装目录保存工具资源，目标项目历史和业务源码保持在目标项目。未知已有文件不会被模板覆盖。

建议在目标项目的 `.gitignore` 中忽略 `.evolve-local/`。`evolve/history.db` 可能包含命令输出与项目上下文，是否进入版本管理由你按协作方式决定；避免多人同时编辑同一份 SQLite 历史。备份与恢复使用维护工具。

## 项目知识和经验

项目知识的建立与修改先展示具体内容，由你接受、拒绝或延期。附带建议可以延期；若文档本身是任务成果，实际应用并检查后才算完成。

`evolve/project.md` 作为统一导航，`codemap.md` 说明实现与检查位置，`domain.md` 保存业务术语，`specs/<能力>/spec.md` 保存正式行为，`decisions/` 保存重要取舍，`guides/` 按需保存开发、架构与数据说明。已有资料初次可映射原位置；后续新增与修订统一沉淀到 `evolve/`，涉及旧主题时登记完整新正文及替代范围，保留原来源。

每次方案会声明知识影响。导致规格、概念、接口或地图失真的变化属于必要交付；封存前核对当前成果和知识处理。可验证的路径移动在准确范围授权下可自动维护；业务含义、约束和重要决定集中确认。分类模板及写作、图文要求随插件提供，格式检查和实际内容验收分别进行。

经验来自真实工作发现并保留来源和适用边界。下次可以检索、采用或拒绝；反例会使经验待复审。候选经验不会自动成为正式规则或新的修改授权。

## 查看状态

进入、切换与收尾使用 `[Evolve · Skill · 阶段]` 标识。结果分别说明本阶段完成和整个目标完成；等待确认、暂停、受阻、取消都有实际成果、剩余项与接手指令。代码实施完成后仍需验收、必需知识收尾及封存。

CLI 回执的 workflow 给出 marker、phase_status、stage_complete、goal_complete、remaining、next_steps 和依据编号。next_steps 的自然语言 prompt 可直接发送；query_command 仅对只读动作提供。建议本身不授予执行权限。

status 和 doctor 的 readiness 按记录、知识、业务文件、检查及外部执行分别报告条件。ready 表示观察到的前置条件，业务测试和实际验收另行执行。activation 区分会话包摘要核对与尚未观察到的宿主启用。

对 AI 说“使用 Evolve 查看当前工作进度”，或运行：

```bash
python3 "$HOME/.local/share/evolve/runtime/evolve.py" --project /absolute/path/my-project status
python3 "$HOME/.local/share/evolve/runtime/evolve.py" --project /absolute/path/my-project status "总计修复"
python3 "$HOME/.local/share/evolve/runtime/evolve.py" --project /absolute/path/my-project history
```

替换安装和项目路径。状态及历史查询保持项目文件不变；历史通过表示当时的结果，当前是否仍满足要求需要重新检查。

## 查看工作资料与下一动作

Evolve 在 evolve/changes/<工作ID>/summary.md 保存可阅读的工作摘要；复杂工作按实际内容增加规格、依赖任务图和验收页。它们来自历史记录，编辑不会改变执行状态。手工编辑冲突会保留；可以请求“核对这项工作的派生文档，重建缺失部分”，该操作不重跑业务修改或检查。

可以随时说“使用 Evolve 查看下一步”。引导会结合当前目标、必需检查环境、任务依赖、有效验收和知识收尾给准确入口。失败时分别说明已保存记录、实际文件写入及尚未确认的结果；历史通过不会自动作为当前验收。

## 检查复用与资料整理

可重复且输入可固定的本地检查可以在检查配置候选中设置 `reuse=true`。输入、工具环境、计划及来源完全相同时，Evolve 引用原检查并保留原回执；默认仍运行，环境前置检查和保行为前后检查也始终实际执行。说“本次重新运行类型检查和构建”，AI 会把相应检查放入 fresh_checks；验收中仍需实际检查当前成果和审查条件。HTTP、浏览器及外部数据现场保持实际验证。

经验命中后，AI 记录采用或不采用，并说明对方案或检查的具体影响；完成后用实际结果反馈，无法归因可记录 unknown。没有新发现允许有依据地记录 no_new_learning，不因此创建新规则。

说“查看 Evolve 的 review 资料及保留原因”触发只读 materials；“导出这次验收的审阅副本”从原封存回执建立副本及默认索引。需要清理时，先给出准确集合，再按已有授权删除已结束、无引用、可重建且未手工修改的运行时辅助副本。项目文本或手工笔记仍引用的副本会保留；相对链接也参与核对，计划后新增引用会阻止删除。正式回执仍在 history.db，原证据和未知文件保留。删除中断后先核对原记录，不能重新运行整批清理猜测结果。
