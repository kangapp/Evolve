# 使用说明

本指南对应0.1.0。用户表达目标和授权边界，AI负责定位工作项、准备内部请求并保留真实来源；实际可用方法以安装包的只读status为准。

## 第一个任务：已有项目的小修复

起点：已有源码和检查入口，完整 Evolve 包安装并在当前项目启用，Python 3.11+。从实际宿主发现的 evolve-workflow 入口表达请求，例如：

```text
接入这个项目，梳理总计错误的相关代码，保存短方案，按我确认的范围修复并测试通过。
```

AI 先核对资料和授权；明确修改的简单任务先展示短方案即可在原范围推进。包安装、项目接入、正式知识批准分别处理：init 只建立配置和记录设施，沿用原有代码与资料，不自动写 project.md。

方案包含目标、具体文件范围、完成条件、相关检查和限制。propose 保存原文与任务定义，尚不代表已批准或实施。apply 按实际呈现的当前方案及修改授权写入，每次核对原字节与版本；相关检查失败保留源码和失败证据，修正复测。

任务检查通过后，verify 另行检查规格符合性和项目规范／维护性，并记录逐项 AC、实际观察者和真实检查结果。只请求 verify 时不会修改业务或测试源码；缺测试给出补充方案。已封存工作项允许追加当前现场的验收记录，保留原 Change／Task、历史 VER 和封存截点；当前字节与原实施范围不符时如实受阻，不强行重开实施。审查发现必需问题后，已有完整修改授权可继续修复复查；主观建议与必需问题区分。

最后 archive 重新核对当前现场、最新必需验证、任务及未决审查问题，保存具体完成截点。任务检查通过不会自动封存，附带知识也不会自动批准。源码或检查配置变化后，旧通过不能冒充当前通过。

结果分别查看 implemented、verify 的 status 与 archived。checks_not_passed、blocked、needs_recovery 都需要继续处理。配置与历史保存在目标项目 evolve/config.toml、evolve/history.db；本地 journal、保护备份和协调信息在 .evolve-local/。插件缓存不存目标项目历史。

## 四类日常工作

<a id="daily-application"></a>

### 应用开发

可以说“先展示总计及其报告的完整 spec 和任务清单，按我接受的范围实现、测试并封存”。每个切片有独立用户结果和检查；消费上游结果时等待该 Task 的真实验收。最终集成检查会读取实际整个目录，其他未完成修改也可能使它失败。单 Task 通过不能代填整项完成；修复相关问题后重新验收，历史失败保留。具体过程见下文复杂方案。

<a id="daily-sql"></a>

### SQL 开发

可以说“只修改这份 SQL，按指定业务日期、最新版本、空值和退款口径对账，保留原独立预期，通过后封存”。先查清粒度、来源范围与观察时点，原症状和修复后使用同一判据。相关任务仍走通用方案、apply、verify、archive；当前交付的是 SQL 和指定样例验证。数据调查与导出细节见下文。

<a id="daily-diagnosis"></a>

### 异常排查

可以说“只调查这次金额异常，保留实际失败和下一步方案，暂不修复”，或“只验收已封存项当前现场”。缺必要测试模块或环境时，给出具体受阻项；verify 不创建替代测试、修改配置或还原手改代码。一次未复现只说明本次观察，不能称根除。换会话用明确目标恢复原调查或工作项，旧聊天不是唯一来源。

<a id="daily-knowledge"></a>

### 血缘与知识整理

可以说“从已保存的有限关系底稿导出图和报告，不重新查业务；附带项目说明先给候选并延期”。报告保留原观察范围与当前未核实项，源文件移走仍可导出原事实。候选延期不会写正式正文或建立权威；已通过的实现可封存，用户要求的必需正式文档则仍需具体批准、实际应用和验收。原文修订和规则各由其 owner 处理。

## 复杂方案与多任务

复杂工作先整体呈现 spec、用户结果、独立验证方式和真实依赖，接受后按就绪条件逐项实施。每项完成检查不代表整项通过；有“上游验收通过”依赖时，还要完成该任务的独立验收才能推进。最终运行整个方案的集成检查和审查，再封存全部成果。只请求 apply 或只验收时保持对应边界。

正常暂停只保存所选任务的部分结果，换会话用 resume 查看全部任务、原授权和下一步。上游实际结果变化只重开相关后继，旧完成记录保留；外部编辑先核对，不自动覆盖。改变目标、缩减验收或重构前后证明仍需当前已开放的对应路径；未开放时明确停止该分支，不降低条件。

必要预重构先保存原行为的实际检查，再改代码并复验相同判据。原检查失败、零测试或判据文件变化时不能声称行为保持。若本轮只想改文件后暂停，先单独准备原证明，之后暂停仍不运行检查；续接或恢复保留原证明，不能把修改后的检查称为重构前结果。该证明只覆盖声明的检查和输入。

需要改变目标时，可以说“将报告格式的要求改为……，说明影响并修订方案”。AI 展示新方案、受影响任务和移出内容；已完成且仍适用的成果保留。移出范围或改写验收条件须明确接受；格式调整沿原接受依据继续。旧结果、失败和审查问题保持可追溯，必要时补做相关任务与最终集成，不要求你手填 REV 或 Task 编号。

## 两个工作项与取消

可以说“报告工作 B 依赖 A 的接口实际验收，其余工作分别推进”。AI 在具体复杂任务中保存真实上游目标、固定版本、所需条件和依据；A 的 Task done 不自动代替接口通过。上游改变或取消时，只阻碍真实依赖项，保留旧完成结果，不偷偷跟随最新版本。需要重绑时先呈现实际方案变化。

同文件或同工作项的写入会协调，无关工作可以推进。检查期间发生其他修改时，保留实际现场并补做验证；验收说明包含的关联工作和依赖，不声称单任务独立隔离。不同 owner 的正式文件变更仍逐项批准并检查实际组合，批量批准不跳过冲突。

可以明确说“取消工作 A，保留已做结果和文件”。相关动作安全结束后，AI 登记取消及理由；仍在运行或结果未知时保留占用，先核实原动作。取消不回滚业务或正式资料，不抹除已完成 Task、历史验收或已发生效果；已封存工作保持原截点。具体字段见[多工作项约定](../shared/multiple-work.md)。实际宿主验收范围见[兼容说明](compatibility.md)。

## 正式文档候选

可以说“把已登记术语文档中总额的定义改成数值之和，先展示完整差异并保存候选”。AI 保存具体正文、基线和内容判据；你可以按候选分别接受、拒绝或延期。内容改变会形成新版本，旧批准不转移。候选通过或 approved 只表示检查／决定已保存；如你已具体批准应用，sync 核对原版本后写入正式文件，verify 再检查实际目标。

若初次建立正式文档，可以说“将这份术语说明登记为初次正式基线，并完成文档任务验收”。AI 展示正文、当前文件状态及内容判据，由你具体决定，再由 init 应用并重新验收实际目标。已有未登记文件可按原字节登记，文件内容无需为登记而改动。目标已经正式登记后，后续修订由 sync 处理。

若文档修订本身是本次成果，可以说“修订正式术语并验收完成”。AI 在方案中注明文档任务，先展示内容并按具体批准应用；未应用或应用后验收未通过不能成功封存。仅作为附带改进的候选可以延期。业务规格同步还需核对对应的实际实现证据。

只验收文档时会重新读取实际内容并追加新记录，保留旧通过和外部编辑；不会自动改回旧正文。同一文档的独立差异可以逐项接受、拒绝或延期；已批准前项应用后，AI 核对真实来源链并检查组合正文，再应用后项，不重复批准未变内容。范围重叠、含义冲突或外部字节会停止相关项。当前已验证 init 建立初次基线后，sync 按实际基线追加独立差异；原初次含义需有明确范围才能证明后续仍保留。外部文档可先展示原正式版本与实际外部全文，经内容检查和具体批准后登记为正式版本；采纳保持文件字节，仍需目标验收。进一步外部编辑、原权威变化或重叠含义会阻止旧提案继续。

可以说“这份正式说明已由其他工具更新，先展示完整差异，确认后采纳当前全文并验收”。AI 保存原正式版本与实际外部观察，具体批准后才登记新权威。旧任务 A 的待审说明被新工作 B 替代时，原内容和决定保留，状态及工作项导航可查看后继；旧批准不能把后来的有效内容改回去。

## 调查而不实施

只需要即时解释时，可以说“解释一下总计为什么不对，暂不留档也不修改”。AI 使用不留档调查，不先 init，不创建历史库或业务工作项。返回的事实与假设来自实际读取和观察，未完成检查会保留限制。

需要以后接续时，可以说“只调查总计错误并保存独立记录，暂不修复”。未接入时先最小接入，再保存独立 analysis run；不会为了调查建立 Change／Task，也不需要 archive。来源、观察时点、原文／输出、事实 F1、假设 H1、未答问题与下一步分开保存。completed 表示本轮结束，partial／inconclusive 仍表示答案有限。外部历史材料注明实际观察者，未知日期不补成今天；只引用未取得的外部原文时不承诺恢复其内容。实际留存的文件与输出当前在历史库的 evidence／blobs 中。

排错先保留能捕捉真实症状的方法、输入、独立预期、环境、原始观察及副作用。运行一次没有失败不等于消除偶发问题；没有权限、无法复现、缺 red 时如实记录。调查可以在已允许的隔离环境复现，新增持久化测试、业务配置或真实环境探针仍须修改授权。

用 status 指定调查 RUN ID 可读原始结论、来源、result_digest、criterion_digest、当前头与后续纠正。明确“沿这次调查继续”才派生 previous；新问题新主题，同标题的多个主题不自动合并。旧头不会分叉，旧结论不覆盖，后继反驳仍关联原 F／H。任务内排查沿仍有效的父执行绑定，阶段已结束则另起独立调查，不继承过期修改权限。

决定修复后，再明确授权和实际文件范围。AI 呈现短方案，引用原调查及症状判据，走 apply、verify 与 archive。verify 除真实检查和双维审查外还保存原判据的当前复验；不能换宽松条件、删断言或只凭退出 0 声称完成。只请求调查或只验收都不会自动开始修复。

## 数据调查、SQL 与有限血缘报告

可以说“只调查这两个业务日期的订单口径和表间关系，保存来源、粒度、覆盖范围和未知项，不修改 SQL”。AI 按实际来源保存 data_context 和有证据的关系；业务日期与实际观察时间分别记录。局部图只覆盖已调查链路；外部数据未重新读取时明确未重观察，本地来源摘要相同也不证明生产数据仍新鲜。

确认修复后，可以说“仅修改这份 SQL，在隔离样例中对账金额和数量，保留原独立预期，通过后封存”。AI 沿普通方案／实施／验收闭环，覆盖声明的日期、业务键、去重、空值与边界；交付 SQL 及样例验证不代表正式补数已执行。实际数据写入需准确候选、目标和范围批准，按[数据操作](../shared/external-work.md)执行；当前仅支持有限同步Python／SQLite机制。

需要报告时，可以说“从刚保存的调查底稿导出 Markdown 血缘报告，不重查业务数据”；也可指定 JSON。AI 用原分析回执绑定保存版本，输出到 `.evolve-local/exports/` 下的新文件；Markdown 的图与正文来自同一关系底稿。导出保留原观察时点、限制与后续纠正，单独留维护记录，不改变分析头。源业务文件已移走时仍可重导已保存材料。输出冲突或失败显示 view_stale，保留底稿及已有文件，改用新路径。重复原请求返回原回执，不能据此宣称文件后来没有变化。具体字段见[数据工作](../shared/data-work.md)。

## 查看状态与只读诊断

```bash
python3 /absolute/path/evolve-package/runtime/evolve.py --project /path/to/project status
python3 /absolute/path/evolve-package/runtime/evolve.py --project /path/to/project status "总计错误"
python3 /absolute/path/evolve-package/runtime/evolve.py --project /path/to/project maintain --method doctor
```

替换上述路径为实际安装根及目标项目根。未接入时 data.project.state=not_connected，不创建记录。已接入时可查看工作项、任务版本与 pending_runs。状态中的 analyses 按调查主题列当前头；指定 RUN ID 可看历史原快照和当前纠正。指定唯一工作项标题或 ID 后，status 另外返回原来实际呈现的短方案、当前 Task 定义及最新历史验收引用，无需回旧聊天找正文。最新验收的 recorded_status 是当时记录，applicability=unconfirmed 表示本次查询没有重新验收，不能直接汇报“当前通过”。knowledge_refs 导航到已批准正式文档；目标字节与批准版本不同时标 unconfirmed，pending_knowledge 中的候选也不自动成为正式约定。标题不唯一时明确选择，不按最近会话猜目标。host_enablement=not_observed 表示运行时未检查宿主启用配置，不能据此宣称已启用插件。

## 正常暂停与换会话

可以明确说“保存当前部分结果，剩余检查和验收下次继续”。AI 通过 apply 的 pause 保存实际进度、未做事项、下一步及原授权；本轮只完成受管文件段，不运行检查，也不将 Task 记成 done。此时 run 的 completed 表示本轮安全结束，outcome=partial 表示任务仍未完成。

新会话可运行 `resume "工作项标题"` 或 `next "工作项标题"`，查看原方案、部分结果、实际失败、授权来源与现场变化；无需旧聊天。两者全程只读，不执行历史命令或自动接管旧 run。明确继续并核对现场及原范围仍有效后，AI 沿旧 run／结果引用启动新的 apply；正常暂停不需要 recover。多目标明确选择，外部编辑保留为待核查事实。项目内经验还需实际生成、检索、采用或拒绝并反馈，不能把读到旧任务称为学习闭环通过。

## 从前次真实工作复用经验

工作结束时，AI 根据本次真实失败、发现和结果记录项目候选经验，保留来源、实际观察与适用限制；没有新发现须在实际检查后记录 no_new_learning，尚未检查保留 pending。没有预置经验也不补造一条。内容和历史保持，候选只作待核实线索，不能替代正式规则、验收标准或用户授权。

第二次同类任务先读取正式知识，再查少量相关经验。可以说“接续原工作，并查一下上次同类问题留下的经验；按当前代码核对是否适用”。AI 查看原版本、范围、来源和当前文件，分别保存检索命中、采用／拒绝的理由及本次工作来源。修复与验证完成后另存实际效果反馈；无法归因时明确 unknown，不能把整单通过算到所有引用上。

反例使经验待复审，停用仍保留旧内容和历史。active 也仅表示限定范围内有支持，不是正式知识批准；业务假设不会因多次引用自动升级。无命中、未完整留档和来源损坏分别报告，必要时回查原始工作与正式资料。当前项目经验消费及双宿主新会话验收已完成；后续规则晋升等能力仍以运行包实际开放方法为准。

可以说“根据这条有实际证据的经验，提出仅适用于本项目整数求和审查的规则，展示全文、来源、反例和局限，具体确认后应用并验收”。AI 先核对经验版本和内容，再交你逐项决定；经验命中或多次使用不会自动成为规则。Learn 只写已具体批准的规则，检查工具改进仍走普通修改。新反例会使已关联规则待复审，保留正文和旧验收，不自动改写；反例到小型检查的完整顺序见[学习循环](../shared/learning-cycle.md)，IMP-010 已按当前 Codex 范围验收。

也可以说“上次列表样例通过，但这次一次性迭代器仍错；先查现有测试漏了什么，再提出最小检查改进，确认后修复并验收”。AI 分别保留旧观察和新反例，说明原经验哪些部分不再适用，并让未执行方案看到变化。缺口是机械问题时优先补现有测试；原断言和独立预期保持，不另建框架或由 Learn 直接改 CI、hook。

检查改进与源码修复分别验证：新检查能识别错误，不代表当前仍错误的源码已通过。完成实际修复与回归后，只对确实采用的建议记录有范围的效果，无法归因保留 unknown。相关规则仍可能需要复审；未经新的具体决定，不改正文或把旧批准套到新依据，未执行方案也不会因别的任务成功而自动完成。

## 正式知识与本地恢复

初次基线先呈现具体候选，再按候选版本、内容摘要和目标基线批准，由 init 应用并核对实际文件。通用“实现并完成”不会隐含批准正式知识。后续正式文档修订由 sync 处理；init、sync 和 learn 共用具体检查、逐项决定、真实应用和任务验收协议；外部采纳须具体审阅当前全文，不能把现场观察本身当正式批准。

中断后先核对现场。maintain recover 只处理已登记的本地步骤：原字节可继续、已为候选仅补事实、第三种内容保留冲突；不会重跑旧检查或业务命令，不把恢复当测试通过。运行进程尚未确认停止时不会接管。完整档案backup／restore及14／15→16定向升级按[完整档案维护](../shared/recovery.md)操作；恢复不作为业务检查通过。

## 具体数据修改、超时与补偿

受控本地SQLite路径已按当前Codex范围通过；这不是生产或远程provider证明，具体适用范围见[兼容说明](compatibility.md)。可以这样表达完整请求：

> 仅在这个隔离 SQLite 项目，将 ledger 的 id=1 从 10 调整为 20。先读取入口、helper、别名配置和间接 SQL，核对真实目标身份与前置，呈现有限候选和检查方案；按我对准确候选的批准执行，再独立验收并封存。不要修改原独立测试。

AI 使用[数据操作协议](../shared/external-work.md)准备当前任务和候选，具体批准后才派发。命令成功、实际数据效果、任务检查与最终验收分别报告。固定本地机制的组件测试会真实修改临时 SQLite；它们不是远程或正式目标验收。

遇到超时或丢回执，先说“只核实刚才那次操作，不要再发”。AI 用原 operation 的只读核实，不换 ID 重发；来源查询失败仍保持未知。取消只撤销后续派发，已经发生的效果继续保留。效果完全查明后若要修正，另呈现关联原操作的新补偿方案及准确批准。恢复 Evolve 档案不会回滚 ledger 或其他业务数据，恢复后仍须核实实际目标。

## AI 使用的工具接口

用户无需填写内部编号。宿主 AI 使用[请求协议](../shared/protocol.md)准备 JSON，调用 `--request <文件>` 或 `--request -`。工具返回系统生成的 request_context 和 input_bindings；重试合并原绑定与原输入，避免重新猜版本。纯查询不接受写请求。

## 按资料缺口梳理

Evolve 在方案、调查或续接实施前说明本轮梳理深度、理由、范围、关键未知和停止条件。已知局部目标可轻量核对；链路或口径不清则定向深入；整体梳理请求或缺少可信全貌时做全局梳理。深度与任务复杂度分别判断，已有可信背景可复用，不要求用户每次选择级别。具体执行指引见[按缺口梳理项目](../shared/context.md)。

## 只读历史

由 AI 调用 `python3 "<插件根>/runtime/evolve.py" --project "<目标项目根>" history` 查看已登记运行；后接实际 RUN ID 可查看准确保存结果、摘要及来源核查。查询不执行检查、不接入或改档案。历史通过不表示当前仍适用，历史授权也不授予新修改权；当前复验仍走 verify。
