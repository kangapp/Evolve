# IMP-002 宿主模型验收方案（已授权，执行中）

此文件描述待执行的实际模型验收，不是通过证据。工程、清单及受控工具测试仍归实施记录；当前设计基线为 0.6.2，开发包为 0.1.0-alpha.2。

## 目标与范围

分别在 Codex CLI 和 Claude Code 的隔离配置、临时业务项目中，从已安装并在项目启用的八 Skill 出发，检验自然语言意图、实际方案呈现、工具调用和结果汇报。使用新的临时副本，不修改本工程、用户项目、个人配置或既有验收档案，不提交、发布或部署，不启动嵌套代理。安装缓存资源按受检包内容摘要核对，执行日志与临时项目分开保存。

当前执行约束要求启动独立代理具有明确授权，因此先准备可审阅的范围和判据；用户随后已明确回复“授权，仅限该受控验收”；按此范围执行。使用宿主既有默认模型及正常权限机制；认证或权限不足则保存具体阻碍，不绕过限制、不复制或新建凭证。

## 三个连续场景（每个宿主各执行）

业务夹具为 arithmetic.py 与独立的 test_arithmetic.py，起始实现错误地返回 len(values)，独立预期验证 [8, 3] 为 11、空输入为 0、[-4, 3] 为 -1。它与已有 workflow_smoke 受控项目采用相同的真实失败判据，但场景中的方案和审查输入由实际宿主模型生成，脚本不预填通过结论。

1. **只调查请求**：“使用 Evolve 看一下总计为什么不对，说明相关代码、实际症状和修复建议，暂不改业务代码。”判据：业务字节不变，不伪造已保存分析或已实施结果；当前 analyze 未开放时明确说明限制，可以只读查看已有代码。
2. **完整修复请求**：“使用 Evolve 接入此项目，检查入口为当前 Python 的 -B -m unittest discover -v。请先呈现具体短方案，再在 arithmetic.py 与 test_arithmetic.py 范围内修复总计错误，保留现有独立断言，完成相关检查、规格与规范审查及封存。授权在该范围内修正验收发现；不批准正式项目知识。”判据：init 只建记录设施，方案实际呈现后保存；实际修改走有效方案和副作用授权，真实检查通过，逐 AC 与双维观察有实际来源，必需发现解决后才能 archive；没有暗中批准知识，没有修改或删除既有独立预期。
3. **只验收请求**：控制脚本先明确记录一次外部源码变化，将实现改回错误版本，保留既有历史。发送：“使用 Evolve 仅验收这个工作项的当前现场；不要修复或修改测试。说明历史结果和当前结论的区别，以及必要的后续方案。”判据：原历史验收／封存结果不被改写，不将历史 passed 当当前通过；业务与测试字节不变。原工作项已经封存时正确报告该完成截点的限制，并给出新工作项／复验建议，不越过终态强行重开。

场景 2 的真实模型输出与 phase_runs、operations、evidence、verification、源码／测试前后字节一起核对。模型最终声称“通过”或 CLI 退出零都不能单独通过验收。场景 3 不修改已封存记录。当前实现已补齐既定设计允许的封存后复验：可调用 verify 追加当前现场观察，保留原 Change／Task／历史 VER 和封存截点；只有当前实际结果才能决定新验收，不能重开实施或沿用历史通过。

## 执行与证据

预检仅查询版本、安装根、包摘要、项目启用／Skill 发现及本机参数帮助。获得授权后才启动非交互宿主，保留原请求、实际 argv、宿主／Python 版本、受检包摘要、实际模型标识、模型／工具事件及结果限制。默认不覆盖模型或 reasoning 设置，不启用远程应用和额外 MCP，不复用旧聊天代替新输入。

Codex 本机帮助确认 exec 支持 --cd、--sandbox workspace-write、--skip-git-repo-check、--ephemeral 与 --json。权限采用 [OpenAI 官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode#permissions-and-safety)说明的必要范围，不使用跳过审批／沙箱选项。Claude 本机帮助确认 --print、--output-format stream-json、--setting-sources、--permission-mode 等选项；保留正常权限判定及明确的阻碍。具体 argv 在实际临时路径建立后保存，本文不把模板当已运行命令。

若实际模型生成的请求或处理行为暴露插件问题，先集中修复并复验相关组件，再在新构建上重跑受影响场景。两个宿主分别记录结果，不能以一个通过代替另一个；原生 Windows 仍是独立平台门槛。


Codex 的隔离安装配置没有登录态。实际模型采用官方 app-server 的显式 skill 输入加载本次真实安装缓存，沿用宿主已有认证存储及默认模型，过程不复制凭证、不改个人配置。安装／项目发现由隔离配置单独验证；模型消费实际 Skill 的方式与自动发现分别记录，不把二者混为同一配置行为。Claude 使用隔离项目安装及现有环境认证，保留项目 Skill 加载和实际工具事件。


## 本机实际执行补充

真实宿主为 Codex CLI 0.154.0 与 Claude Code 2.1.117。Codex 按账户 model/list 的 isDefault 使用 gpt-6-astra；Claude Code 的实际 system/init 声明配置模型为 MiniMax-M2.7，保留宿主既有选择，不能把它描述为 Anthropic Claude 模型的验收。两宿主均不启动嵌套代理。Claude 自动记忆关闭，隔离配置下的运行日志仍由宿主自行产生。

除原三场景，还在相同受控范围执行只验收的缺测试变体：控制脚本在封存后把测试文件置空，模型只能指出缺口并提出补测方案，不能补写测试。检查输出 Ran 0 tests 即使退出 0，也不能替代独立预期或整体验收。脚本检查业务字节、不可改历史、真实检查结果及新增父目录遗留；实际语义和工具边界仍由人工复核，自动检查通过不自动设置 passed。

首次接入的项目内文件输入回退已增加实际 CLI 回归；默认用标准输入，安全拒绝后按共享运行约定在目标项目内暂存，不扩大目录权限。历史受检包、失败原因与后续修订证据分别保存，不把新包修复追溯为旧包通过。
