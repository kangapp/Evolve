# IMP-012：完整一致备份与安全档案恢复

前置：[M2 当前 Codex 范围门槛](../imp011/milestone-m2-codex-alpha21.json)已通过。后续实施、临时受控验收及必要修复复验沿[实际统一授权](../continuation-authorization-20261101.json)执行，不逐轮询问。仅临时项目与隔离宿主配置，不发布、不执行真实生产数据。

## 实现理解与取舍

恢复集合是项目档案：SQLite 的一致副本、工具配置、已批准受管正式文档、数据库中的方案快照及实际留存的证据／附件。业务源码与真实数据不进入恢复集合。已登记版本从该库快照所指向的不可变 blob 组装；当前未批准手改单列保护附录，不把“库快照＋随后任意当前文件”称一致包。外部来源只有引用而未留存正文时如实列限制。

选择有清单和摘要的目录包，保留当前的 Python 标准库与本地文件协议，不引入通用存储适配层。接口只开放 maintain.backup、maintain.restore，以及本轮确需的定向 maintain.upgrade。备份成本／集合、维护屏障、恢复日志各集中维护，不让普通 owner 理解换库步骤。

恢复采用保守排空方式：独立 control journal 的屏障先阻止新受管操作，确认旧本地执行与检查进程已停止后才换库。活跃或无法判断的执行拒绝换库，不提供绕过开关，不自动杀用户进程。真实进程故障测试由测试控制侧结束自己的子进程。外部编辑器不受工具锁保证，替换前再次核对字节。

新增恢复与保护语义用 protocol 15／schema 4 隔离旧写入器；既有 alpha.21／protocol 14 完整包保留。仅提供明确的 14→15 定向升级，先保护现场、检查旧实例、展示准确变更，显式维护调用后实施；init 不迁移、不改身份、不清库。升级与恢复均更换 epoch，旧请求不得重放。

## 依赖任务与验收

1. **有界一致归档**：快照固定 checkpoint／注册集合，校验 SQLite 完整性、引用、全部 blob／文件摘要；保存配置／知识实际差异附录；估算集合与磁盘空间，超限／变化失败不截断或假称完整。每日首次保护复用该集合与同日有效副本，保留旧保护点，不增加归档完成时的额外全量备份。
   验证：数据库快照后文档／附件变化、缺文件、损坏摘要、未解决 file journal、容量不足、已有同日包损坏均实际拒绝；原字节保留。
2. **维护协调与定向升级**：持久屏障与受管写入共用控制临界区；原 DB、sidecar 和资料先保护，旧执行者／检查排空后才改变集合。为数据库损坏时识别包外受管正式文件保存最小保护索引，它不是第二套正式知识权威。控制文件与数据库不一致时停止推断，不借索引批准或改写知识。
   验证：活跃旧进程、已打开旧连接、旧包新请求、屏障进程崩溃及恢复后旧 epoch 请求拒绝；原协议字段仅通过显式维护升级，不隐式重建。
3. **具体恢复方案与逐步换库**：先校验准确包、同项目、版本、路径与摘要，给出集合差异和当前字节依据，再按准确 plan／包摘要执行。保护所有现存档案（损坏库直接保留原始字节及 sidecar），当前额外受管文档保护并隔离，未登记用户文件留原位，目标碰撞停止覆盖。每个替换步骤可核原值／候选／第三种值；新库安装新 epoch 与 guard，成功核查后解除屏障。
   验证：损坏包、路径穿越／链接、包外受管文件、未登记用户文件冲突、配置／知识／库替换前后各处真实 os._exit 故障、恢复期间第三方改字节。恢复不重跑包内命令、历史检查或业务操作。
4. **保留外部未决保护**：本切片用受控最小引用演练保护集合，保存当前已知 running／unknown 引用和资源；旧包不能覆盖或遗失它们。索引缺失／互相矛盾明确需核实，不按“旧库没记录”放行。实际目标派发和效果核实留到 IMP-013，不能用记录演练替代实际执行验收。
   验证：更旧档案恢复、保护缺失、冲突引用、屏障故障均保留需核实状态；本阶段 external.execute 仍不可用。
5. **工程与真实宿主验收**：补 troubleshooting 完整恢复指南、development 故障演练、升级及数据边界，更新实际方法与版本。新完整包先组件／公共 CLI／隔离安装，再按冻结临时材料由 Codex 完成跨会话备份、损坏／倒退恢复、当前现场核查；语义复核通过后才进 IMP-013。
