## 固定、可验证的案例

使用临时 Python 求和项目。初始 total.py 返回 len，test_total.py 保留正数、空列表、负数三个独立字面量；guard.py 是只读的独立检查验证器。它检查原断言未移除，再将候选测试分别运行于正确 sum、错误 count、以及“列表正确但一次性迭代器返回 0”的固定实现。只有正确实现绿、两个错误实现红才返回零。预期由固定字面量与人工给定的生成器例子 `iter([5,-2]) → 3` 决定，不从待测实现计算。

guide.md 只用于受控正式规则。先保留原文初次登记，再由 learn 具体批准应用“核对整数求和时使用独立字面量样例，注明观察范围。”。完整原文和准确批准将在原生方案中列明；出现反例后本阶段不重写或重新批准规则，明确保留待复审来源。

1. **原列表工作与真实来源**：A 实际 red／修复／unit／验收封存，记录只覆盖原列表样例的 observed 候选经验。该经验不是完整输入域保证。实际交付有范围规则，再保存 C 的未执行复杂方案及采用记录，效果仍 unknown。
2. **第二次任务的覆盖缺口**：控制侧只将 total.py 换成列表正确、迭代器错误的固定实现。B 保留 unit，并必需 guard；实际 unit 绿、guard 红、独立生成器断言失败。保存对应工作结果、检索／采用或拒绝的真实决定，再记录同定义、决定之后的 counterexample。旧列表事实不改写成错误；反例针对新输入域的不足。
3. **传播与具体检查方案**：旧经验不再推荐，已应用规则仍保留原字节但来源 needs_review，当前目标验收 blocked；C 的旧采用和上下文变化可恢复，不能自动执行。检查现有测试与 guard 后，只提出完整 B 新 REV：CHECK 负责保留旧断言并增加生成器字面量检查；FIX 负责 total.py，经 CHECK 的实际 Task 验收后推进。保存候选经验和未接受方案，本轮不改业务／测试文件。
4. **原 owner 实施小型检查**：具体接受准确新 REV，普通 apply 只实施 CHECK 的 test_total.py，learn 只保存检索与采用。原 guard 必须真实捕捉错误变体并放行正确变体；Task 验收后仍保留 total.py 的错误现场，不能把 guard 的成功当当前生产函数已通过。
5. **修复及联合验收**：FIX 经固定前置核查后只修 total.py。原 unit、guard、逐项验收及整体验收通过后封存 B，保留旧失败与旧 REV；guide 和 guard 不改，C 不自动完成。
6. **有限效果与未执行方案续接**：只对实际采用的新经验，以 CHECK 的真实同定义后验来源记录 helped／not_helped／unknown 的有界观察；不从整单通过推断全部引用有效，不自动 active。恢复 C 时展示旧经验／规则来源的待复审及测试上下文变化，保留其未执行状态；规则正文不自动修改。
