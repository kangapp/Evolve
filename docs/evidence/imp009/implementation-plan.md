# IMP-009 实施与验证

前置 IMP-006／007 已按当前 Codex 范围通过，IMP-008 已以完整 alpha.15 包完成五新会话／61 条实际命令及语义复核，见[阶段门槛](../imp008/stage-gate-codex-alpha15.json)。当前源基线 alpha.15／protocol 12／schema 4，499 项回归通过。本阶段目标是工作项隔离与真实前置核查，不增加并行代理或后台调度器。

## 已查明的实现与缺口

- 当前已有 project 短锁、Change claim、规范化文件 claim，检查在短锁之外运行；不同 owner 共用同文件占用。需用真实进程证明同 Change／同文件互斥、无关 Change 可继续和混合现场不会假通过。
- 当前复杂 Task 只接受同 Change 的条件依赖，propose 根上的跨 Change 字段返回 unavailable；尚无可用的 maintain.cancel。只改某个数据库状态不能替代取消接口验收。
- 当前 VER 保存整个工作目录指纹，复杂 Task 另有 scope／声明上下文／依赖输入的局部依据。跨项核查必须保留这种区别：无法证明检查输入范围时采用保守的当前现场核对；显式声明和已验证的局部依据才能复用，不能从“文件名不同”推断独立。
- 已有同文件批准差异链与外部全文采纳，不重新建设知识存储；需要补跨工作项／owner 的真实竞争组合。正式数据执行和完整档案恢复仍属后续阶段。

## 实施顺序与判据

1. **安全取消与占用**：maintain.cancel 只登记明确指定工作项的停止决定和理由，冻结当前版本；保留已发生字节、完成结果和历史 VER，不自动撤回知识。实际执行／未知效果尚占用时拒绝并保留占用，不中止进程猜结果。只为安全结束的本地工作开放取消；元数据中断恢复只核实已提交取消事实，不重发业务动作。验证：真实 owner API、重试、旧版本、在途拒绝、已封存拒绝、已提交中断恢复。
2. **跨工作项前置**：复用 Task 定义，新增有界的外部依赖引用（同一项目的实际 Change／Task／固定版本／条件／依据），不添加通用执行表达式或任务平台。声明条件仍限完成、实际验收、成果存在及正式知识应用。核对全项目实际任务图的环；旧完成不替代接口验收。上游取消、定义／源结果／当前必需依据改变时，只使真实后继需重核；保留旧结果和正式文件。验证：A/B 条件、多个来源、版本变化与取消、循环、无关 C 可继续、拒绝裸 done 代替 VER。
3. **实施及联合现场**：每次文件写入、命令派发和结果提交都重核当前依赖与 claim。跨项变化发生在检查期间时不写当前通过；保存当时包含的关联修改和依赖快照。验证：真实子进程门闩控制并发和外部手改；只读查询字节不变；受阻工作不会禁止无关工作项推进。
4. **知识与工程收口**：沿现有批准／owner／文件链组合 A/B 的 init／sync／learn 差异；非冲突顺序推进，重叠／外部变化保留双方，批量批准不绕过冲突。更新共享指引、工程清单及独立完整包，升级为 alpha.16／protocol 13／schema 4；完整旧 alpha.15 写入器拒绝新语义。执行相关组件、当前全量回归、公共 CLI 和具体当前 Codex 受控场景，逐条复核实际模型行为后才通过阶段门槛。

每步发现的问题集中保存、同范围修复复验。新字段在完整呈现、语义摘要及 REV 比较中保持；不能通过仅改排版引入前置或降低验收。取消不抹除物理效果，关系不等于授权，当前分支验证不冒充 V 条目全部能力或 M2 集成通过。
