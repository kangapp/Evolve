# IMP-008 实施与验证

前置：IMP-003 已通过，IMP-006 按用户 2026-11-01“先按 Codex 验收”的当前范围通过，见[门槛](../imp006/stage-gate-codex-alpha14.json)。当前基线为完整 alpha.14／protocol 11／schema 4。只在隔离项目验证，不接正式数据库，不修改个人配置、不发布。新内核包独立保留；旧试用资料不自动迁移。

## 交付与顺序

1. **有范围的数据观察**：analyze 沿原 run／Evidence 保存可选 `analysis.data_context`，包含对象、业务日期、粒度、口径、来源引用、覆盖和限制。业务日期与来源实际观察时间分开；未知值需要限制，不能形成无条件完整回答。来源的 `data_scope` 必须覆盖本次对象和日期，扩大日期不能仅改报告标题重用旧观察。普通代码调查不要求数据字段。
2. **关系底稿与续接**：可选 `analysis.relationships` 保存端点、转换、observed／inferred／unknown、直接来源和限制；只覆盖实际观察范围。沿既有 previous／corrects 保存后继，默认与指定历史查询保留原版本及纠正。查询只核本地文件摘要；外部数据一律明确未重新观察，不从未变的源码推断生产数据未变。
3. **独立导出**：开放 maintain.export，明确绑定已完成分析的 run＋result_digest，输出只在 `.evolve-local/exports/`。Markdown（含同底稿 Mermaid）及 JSON 从保存事实生成；保留源版本、生成时间、原观察时点和后续纠正，不读业务文件、不运行查询。单独维护 run、只引用原分析；输出冲突保留原文件，视图失败为 VIEW_STALE，不改变分析头或成果。原渲染正文先保存 blob；中断恢复仅观察已发生输出，不补查询或重写第三方文件。
4. **真实 SQL 小流程**：使用现有 propose／apply／verify／archive 的短方案接口，在临时 SQLite 固定夹具验证两个业务日期、订单粒度、去重、金额／数量、空值及边界。独立字面量预期由测试夹具给出；先保存实际失败，再修改 SQL，经同判据及回归通过后封存。声明只交付 SQL 和隔离样例验证，未执行正式补数。另存独立数据调查和有限血缘，无虚构 Change。复杂任务接口沿 IMP-006 已有产物，后续组合分支由 IMP-011 核验，不把本轮短方案夹具算成复杂 SQL 实测。
5. **工程闭环**：更新按需资料及 Skill 指针、usage 的数据／导出示例和版本清单；alpha.15／protocol 12／schema 4，旧完整 alpha.14 写入器拒绝新协议且不改库。导出前置定位不调用会读业务现场的通用 status；源码、独立完整包、公共 CLI 和适用全量回归分别验证。

## 验证口径

- 通过实际 analyze 接口验证日期范围、来源时点和来源范围，拒绝未知引用、无证据 observed 关系及扩大日期复用；partial／inconclusive 与 run completed 保持独立。真实输入变化、不同主题和后继纠正不会覆盖原事实。
- 通过维护接口验证同一底稿生成图与报告、JSON、重复请求幂等、旧 source 精确导出、后续纠正、源业务被删除后仍可重导；输出只可新增授权位置的普通文件。输出错误保留已记录分析；真实进程中断后恢复不再查询或重写输出。
- SQL 的真实检查同时包含必需日期过滤、重复业务键、退款／空值、按指定粒度对账和不适用日期；保留原断言和失败输出。当前数据时效只限观察和声明的夹具版本。
- V-048—059／072—084／129／130 按具体分支保留证据；其他切片负责的并发、正式数据执行和完整恢复不借此宣称通过。阶段通过仍需当前实际 Codex 场景及语义审阅；准备和模拟观察不能冒充模型行为。

正式数据执行继续 unavailable；正式知识另经具体批准及对应 owner，不由数据或血缘关键词自动授权。
