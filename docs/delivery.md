# 实施、验收与决策

设计基线：**0.6.2**；更新：2026-10-31。M0 仅为设计修订；以下 V 条目均为未来实现验收，文档和图册校验不代表插件功能、数据库恢复或宿主已通过。

<a id="test-boundaries"></a>

## 验证方法与范围

实现阶段使用临时目录、临时数据库、受控分支和可控测试目标，按影响执行测试与必要回归。关注实际事实、来源、授权、状态与中断行为，不只匹配模板标题，不做实现自证式镜像测试。

覆盖模型／引用／状态、SQLite 事务、文件快照、指纹、幂等、并发、恢复及外部未知。正式环境执行须单独具体授权；模拟成功不能替代真实业务验证。记录每个 V 的实际环境、方法、结果和证据，不能因设计写清而标 passed。

## 唯一验收清单

V-001—V-084 保留原标识并更新当前判据；旧逐字内容在 [0.5.6 快照](archive/pre-revision-0.5.6-20261031.zip)。V-009、V-040、V-068 的旧专属能力退出范围，不是测试通过；混合条目保留有效部分。V-085—V-110 覆盖需求收敛，V-111—V-125 覆盖上一轮严格审核，V-126—V-137 覆盖 Matt 对比采用，V-138—V-140 覆盖插件工程与用户文档交付补充。0.6.0 原文在 [审核前快照](archive/pre-review-0.6.0-20261031.zip)。

V 编号是可追溯断言，不是要求建立同数量测试文件或独立工作流。同一代表场景可以覆盖多个 V；实现按普通迭代、正式知识、上下文／学习、多任务、外部操作、维护恢复和宿主七组组织演练，记录断言到实际证据的映射，避免重复跑等价检查。

- **V-001 新项目**：init 只接记录设施、导航和基线候选；业务骨架按普通已授权 Change 实施，未知选型先澄清。
- **V-002 已有项目**：沿用源码、测试、资料与映射，不覆盖；事实、推断、风险和未知可区分。
- **V-003 重试**：同操作 init、任务登记、知识应用和封存仅一次有效结果；同 ID 异输入拒绝。
- **V-004 阶段职责**：propose 只规划；apply 只实施有效范围；明确完整请求可连续调用 verify，单阶段不越界。
- **V-005 续接**：无旧聊天恢复有效方案、任务、问题、失败尝试、证据与下一步；多目标不误选。
- **V-006 修订失效**：相关源码、AC、依赖或检查约定变化重核旧证据，保留旧结果；无关展示变化不全量失效。
- **V-007 轻量变更**：短方案可内联保存，纯文案无虚构行为规格；有实际检查和结果依据。
- **V-008 真实验证**：passed／failed／not_run／blocked 及人工观察区分，退出 0 不自动证明所有 AC。
- **V-009 原发布准备**：退出当前范围：不建设发布准备或部署执行器；外部数据执行另按 V-103—V-105。
- **V-010 成果封存**：必需成果实际验收通过后可封存，附带知识待审单列；文档本身是必需交付物时不能待审即完成。
- **V-011 同步冲突**：具体批准与目标基线均有效才应用；另一任务先改基线后不得覆盖；重复应用不复制条目。
- **V-012 多步骤中断**：prepared、文件替换和数据库 finalize 前后失败均可恢复；第三方编辑保留冲突。
- **V-013 备份恢复**：包含历史与必需附件；损坏包、越界路径拒绝；恢复后现场差异重新核对。
- **V-014 并发边界**：多任务独立推进；旧版本写入、资源重叠和同 Change 竞争受控；不声称能锁所有编辑器。
- **V-015 Git 行为**：数据库随版本保存；分叉保留双方，不自动选分支或合并；Git 不回退真实数据。
- **V-016 任务和编号**：依赖无环、条件不满足不能就绪；局部 TASK 带 CHG；废弃编号不复用。
- **V-017 快照和视图**：当前文档覆盖后旧字节可查；直接改生成表不伪造数据库完成或批准。
- **V-018 宿主适配**：两个宿主在 M1 分别完成发现、入口、基础实施验证与跨会话续接；未实现范围如实说明。
- **V-019 命令归属**：八个 Skill 各司其职；十四动作各唯一 owner，直接调用与路由门禁一致。
- **V-020 执行结果承接**：run 输入核查与封存结果可恢复范围；不新建独立交接／回执状态机。
- **V-021 输入核查**：业务依据变更拒绝旧结果；无关事件／知识追加不误判；新重大方案不沿用旧接受。
- **V-022 多接收方**：同 VER／来源 run 可供封存和后继任务核查；各自记录采用理由；不设置已消费标志。
- **V-023 阶段中断**：start、子事实提交、finish 前中断保留已做事实；恢复不重复业务或补造完整成功。
- **V-024 职责边界**：propose 不改实现，verify 不静默修复，router 不代写，maintain 不重发外部未知。
- **V-025 资源与版本**：安装根改变仍定位公共资源；缺内核或未知更高 schema 只读诊断，不无记录降级。
- **V-026 查询与观察登记**：本地查询纯读；明确外部 reconcile 由 apply 留实际观察，不把查询暗中转数据执行。
- **V-027 经验承接**：保存适用经验版本和采用结果；无新发现允许；正式规则无具体批准不写。
- **V-028 轮转范围**：显式单阶段不越界；完整实施验证请求在范围内连续，新增关键选择只阻碍相关工作。
- **V-029 纯查询**：status／next／resume／history／doctor／learn search 和只读 review 不写库、guard、索引或备份。
- **V-030 多来源复用**：多个必需来源逐项核查；归档位置变化有证明可复用，语义变化不放行；无组合发布要求。
- **V-031 阶段幂等**：start／finish 回执丢失仅一个 run 和结果；prepare 后前置或 epoch 变更拒绝过期请求。
- **V-032 无 OP 中断**：源码已改而任务未登记，recover --run 可保留现场事实，不凭文件存在写 done。
- **V-033 换库中断**：restore journal 独立于被替换库，保护旧历史和外部未决引用；旧 epoch 不重放。
- **V-034 损坏恢复**：无法 API 备份时保护原库及 sidecar；保护失败不替换；正常前移不误报回退。
- **V-035 备份截止点**：不递归打包自身／旧备份；清单解释进行中 run；备份不触发备份，实际已提交不回滚。
- **V-036 外部结果**：reconcile 失败不覆盖最近确证；unknown 保留相关资源占用；补偿核对自身候选。
- **V-037 验收范围**：部分通过、最新必需检查失败、只取消 TASK 未移出 AC 均不能完整通过。
- **V-038 部分同步**：批准且验证／依赖闭合的子集可应用；后续修订使用后继 delta，不重放旧 ADD。
- **V-039 支持归属**：知识检查／策略备份可关联父 run；独立操作新 run；pending 不冒充 no_new_learning。
- **V-040 原个人库晋升**：退出当前范围：不建立 personal 库、两端提交或跨项目恢复；项目规则应用见 V-091。
- **V-041 自然入口与定位**：不强迫逐条阶段命令；唯一目标说明后使用，多目标含糊才询问；内部 ID 自动维护。
- **V-042 字段权威**：正式含义归 Markdown，任务定义／状态归 DB，REV 绑定方案、任务及 AC；视图不双写。
- **V-043 交接追溯**：result 多次引用不复制正文；input_checks 保存用途与拒绝原因，无 H 表或回执 API。
- **V-044 轻量连续**：简单方案快照不依赖聊天，复杂任务升级复用材料；明确连续授权不重复确认。
- **V-045 派生结果**：可封存、知识待审和下一步从依据生成；无新发现不建完整复盘；未知不当通过。
- **V-046 三类意图**：即时问答不建库；analyze 留档但无业务 CHG；任务内排查沿当前有效父 run。
- **V-047 双维副作用**：业务只读分析可写记录；不改业务／正式知识／服务，复现实验核对实际副作用。
- **V-048 结论强度**：事实／假设／未知分开；completed＋partial 不表示根因定位；解释与因果证明有不同标准。
- **V-049 分析续接**：标题按主题链折叠；显式历史 RUN 显示快照与头；明确续查另 run，不串修复链。
- **V-050 分析证据**：可无 VER／AC／TASK；保留来源时点；图文可再生成，必需底稿纳入备份。
- **V-051 转修复**：调查结束不隐含修改；提出方案后等待明确执行确认；新成果重新验收。
- **V-052 分析中断**：事件及时提交，恢复只登记已发生范围，不补造复现或结论；后继继续业务只读。
- **V-053 最小接入**：需要留档且无库可说明后最小接入；不搭应用或造正式规格；缺能力不能声称保存。
- **V-054 接入覆盖**：统一增量 init 记录覆盖和缺口；撤去 records_only／development profile，不把配置存在当开发就绪，也不把梳理深度做成初始化模式。
- **V-055 父阶段边界**：当前授权阶段内排查可沿父 run；已结束后独立调查另建；用户收窄后不继续越界。
- **V-056 分析链并发**：同主题同头只允许一个后继；不同主题可并存；恢复 interrupted 仍是分析 previous 身份。
- **V-057 来源用途**：历史上下文与当前依据分开；必需依据失效阻碍相关判断，局部发现后续纠正可见。
- **V-058 修复归属**：匹配已有活动 CHG 按意图复用；同一分析可支持不同修复；不自动接受新重大方案。
- **V-059 留档意图**：后补记录用实际时间；不留档不删除历史；禁止继续写入时不偷偷 finish；导出不重分析。
- **V-060 留档失败**：已观察与未完整保存分开；外部引用注明限制，恢复不造结论或观察者。
- **V-061 视图与建议**：导出失败只影响视图；导出不移动分析头；next 和 resume 不直接启动修改。
- **V-062 统一入口**：十四动作／八 owner；未知动作不降级执行，release 明示退出，不转译为外部数据写。
- **V-063 自动配置**：生成真实最小配置；支持子集增量写保留其他字节，配置成功不运行命令；不接发布执行器。
- **V-064 目录边界**：evolve／.evolve-local 与既有资料映射受控；无个人库例外，同名冲突不建第二权威。
- **V-065 规范化**：动作、方法、目标、范围冻结；未知子方法不默认 execute；未实现方法 unavailable。
- **V-066 身份定位**：有库缺配置、损坏、多根／身份冲突只诊断，不覆盖或新建；固定身份不可普通重配。
- **V-067 配置与业务**：init 只维护工具约定；业务脚本／验收走 Change；仅调工具配置不重置任务或方案接受。
- **V-068 原发布配置支持**：退出发布父阶段配置例外；所有工具配置调整使用独立 init run，恢复仍由 V-069—V-071 覆盖。
- **V-069 配置恢复**：旧值继续、候选补登记、第三值保留；同 epoch 已提交先幂等返回，旧 epoch 拒绝。
- **V-070 项目恢复**：指定 CHG 仍检查项目级配置和全局恢复阻碍；只读差异不登记，多目标不猜最近会话。
- **V-071 授权续接**：既有有效范围跨会话可续用；新实质内容重确认；历史命令和 resume 不独立授权。
- **V-072 通用成果**：应用／数据共用模型，分析共用 run；不加平台专属表、Skill 或工作流。
- **V-073 按需模板**：最小上下文完整，数据字段只在需要时补；普通应用无需填无关字段或生成空文件。
- **V-074 数据开发**：SQL／模型有方案、任务、对账和证据；只完成脚本不声称正式补数已执行。
- **V-075 数据调查**：日期与资料时点保留；新范围新观察；没有修改授权不改数据或正式知识。
- **V-076 血缘展示**：观察关系保留直接依据、推断和覆盖；图与报告同源，不冒充全局完整生产血缘。
- **V-077 成果泛化**：代码／SQL／文件按实际范围检查；有限观察不关闭全量 AC；档案恢复不恢复真实数据。
- **V-078 意图分流**：数据／文档／血缘关键词不决定动作；来源内容不扩大授权，仅排版重导归维护。
- **V-079 知识职责**：init 初次基线、propose／sync 正式业务含义、learn 规则；统一具体批准，不借补齐越权。
- **V-080 最小来源**：对象、范围、来源、完成标准与限制可识别；记录时间不冒充观察时间，不猜缺失日期。
- **V-081 成果与依据**：外部证据核对象／版本／方法／范围／观察者，未亲自执行可采纳但不冒充自测。
- **V-082 封存与导出**：底稿先保存，导出独立 run 只引用；视图失败不否认已提交，不用重导修改事实。
- **V-083 续接时效**：同主题扩日期保留旧范围；未核外部时效标未知，旧结果作为当前依据需重查。
- **V-084 分析转修复**：纠正结论用后继分析、排版用 export、改实现／正式含义用方案；终态 Change 不重开。
- **V-085 修改授权优先**：“看看异常／如何优化”只调查和给方案；明确修改后才实施；方案呈现不作为用户批准。
- **V-086 简单方案持久化**：明确小修复先呈现短方案，保存正文、范围与检查；无独立 spec 文件也能换会话恢复。
- **V-087 复杂规格与任务**：整体 spec／任务清单确认后按依赖推进，重大修改重确认；每个任务保留测试决定引用。
- **V-088 自适应梳理**：同一项目可选轻量、定向深入、全局；已有背景复用；梳理深度不由代码行数或 profile 代替。
- **V-089 上下文可信度**：来源、范围、观察时点、确定性和后续纠正可核；必需规则不被排名隐藏，只询问关键缺口。
- **V-090 完整请求闭环**：明确实现并测试通过时自动进入相关验证和修正；仅 apply／verify 不扩大阶段或修改权。
- **V-091 集中知识确认**：支持逐项接受／拒绝／延期，初次基线同样需批准；批准绑定具体版本，变化不沿用。
- **V-092 封存解耦**：必需实现验收通过而附带知识待审可封存；漂移清晰可见；必需正式文档未应用或影响验收的冲突仍阻碍。
- **V-093 接纳外部修改**：手改源码不需补走全流程；记录真实或未知来源，相关旧证据重核，不还原用户内容。
- **V-094 多任务隔离**：A/B Change 和多个分析主题共存，分别恢复进度和授权，共享项目知识但不串结果。
- **V-095 重叠冲突**：同文件、共享接口／口径或同 Change 竞争被识别；保留双方，无关任务不全局暂停。
- **V-096 跨任务依赖**：固定目标／版本／条件与依据；取消、替代、上游变更重核；done 不等于验证通过。
- **V-097 混合现场验证**：VER 说明包含的关联修改和依赖，检查前后现场变化不记 current；不伪称单任务隔离通过。
- **V-098 候选线索**：未确认经验可供调查且显著标注；不能成为正式规则、验收标准或写权限，次数不升级。
- **V-099 经验效果**：命中、实际采用、结果与归因限制分开；整单通过不等于所有引用成功，无结果记 unknown。
- **V-100 反例传播**：反例关联经验、规则和未执行方案，复审影响后续建议；规则正文仍经确认修改。
- **V-101 配置影响分组**：仅改显示语言／注释不触发全业务复验；检查命令／范围改变重核相关证据。
- **V-102 备份成本**：当日策略不重复全量备份；移除每阶段完成点备份；容量／采集限制明确，不静默丢唯一证据。
- **V-103 正式写授权**：无环境／对象／范围／脚本候选具体授权不执行；批准后候选或参数实质变化必须重新确认。
- **V-104 未知防重复**：调用前、提交后回执前、登记前中断；同任务和另一任务均不重发未知写入；核实失败保持占用。
- **V-105 恢复外部保护**：旧档案恢复保留已知未决引用；保护缺失不假定安全；补偿独立核对范围和授权。
- **V-106 恢复集合**：包外受管文件保护隔离，未登记用户文件保留，冲突不覆盖；恢复不构成新业务执行授权。
- **V-107 早期宿主闭环**：M1 在两个宿主完成真实最小记录／实施／验证／新会话恢复；文档阅读不算通过。
- **V-108 学习回归案例**：同类第二次任务检查重复背景问题、错误线索、过时知识和重复失败；记录未改善情况。
- **V-109 范围收缩**：主流程不需部署、个人库、外部 Issue 或 worktree；未实现正式数据操作明确不可用。
- **V-110 无隐含业务例外**：init 不自行搭业务骨架；archive 不自动批准知识；工具配置维护不改变业务验收含义。
- **V-111 必需知识成果**：用户要求修订正式文档／规则时，候选未批准、未应用或缺少应用后检查不能完成；附带改进才可延期，不混淆两种目标。
- **V-112 纯知识闭环**：候选内容检查 → 批准 → 对应 owner 应用 → 实际字节及适用验收 → 封存；没有“先应用才可验证、先验收才可应用”的循环，apply 不抢写正式文件。
- **V-113 恢复与在途执行**：维护屏障和外部派发同时竞争、旧执行者仍能写／发请求、换库中断分别演练；排空前不换库，旧 generation／epoch 拒绝，外部未知保护不丢。
- **V-114 一致备份截点**：库快照后文档／附件变更、未登记手改或未解决 journal，不能拼成一致包；权威版本与现场附录分开，保留实际用户字节。
- **V-115 实际执行物绑定**：入口不变而间接 SQL／辅助脚本／配置／连接别名变化，旧批准不得执行变化后的操作；执行清单与实际读取字节一致，无法固定范围则受阻。
- **V-116 取消与部分效果**：派发后撤销／取消任务、failed 但部分写入、reconcile 查询失败，均不自动释放未决占用；保留实际效果及未核实范围，补偿仍需适用授权。
- **V-117 正常会话收尾**：主动暂停／等待确认后保存部分结果并释放已安全结束的本地写段；新会话直接续接，不假报异常，外部 unknown 占用仍在。
- **V-118 同定义修复**：任务先 done、集成失败而 REV 不变，在已有修改授权下引用失败证据重开并修正；仅 verify 不改实施状态，环境受阻不抹已做事实。
- **V-119 同批同文件**：不同 owner 的已批准非冲突改动顺序应用，基线随自身应用推进时以证明链复用批准；实质冲突／外部变化只暂停相关项，不重复批准不变内容。
- **V-120 延期提案过时**：已归档 A 的待审提案被 B 的新行为／提案替代，旧批准不转移、不改回旧含义；保留版本、决定和替代关系，相关查询可发现。
- **V-121 检索降级与完整性**：索引失配、来源不可用、未覆盖和真实无命中区分；可只读回查原文；归档成果／待审差异／反例仍检索得到，缺可选经验不阻断全部工作。
- **V-122 完成前再核查**：测试后、封存前改相关文件／AC／检查配置或新增必需失败，旧 passed 不放行；封存后变化不改历史，当前视图显示依据是否仍适用。
- **V-123 补测职责**：只请求 verify 且缺测试时给补测方案，不写测试源码或持久夹具；完整实施测试授权下交 apply 补充再回 verify，隔离临时检查输出如实记录。
- **V-124 最小学习生产与消费**：M1 在同一项目真实产生一条候选发现及来源，新会话检索、核实、采用或拒绝并保存效果；不能只读取预置数据或用无新发现冒充学习闭环。
- **V-125 增量接入无模式问卷**：分析接入后转开发仅补目标所需资料／检查，无 profile 迁移、业务初始化特例或完整重访谈；已确认信息不重复询问。
- **V-126 完整小流程与真实依赖**：每个实施切片有用户可见结果、独立验证及范围；不按技术层虚构依赖。必要预重构和无法逐批独立通过的广泛迁移说明集成边界，不伪称独立完成。
- **V-127 双维代码审查**：verify 分别检查规格符合性与项目规范／职责和维护性；短方案可作规格依据，无关风格建议不当硬门禁；纯文档不造代码审查。
- **V-128 审查闭环与现场**：相关未提交／未跟踪内容进入审查；发现有依据、影响、处置和复查证据；必需问题未解决不能完成；仅审查不修复，有原范围修改授权才返回 apply。
- **V-129 症状判据前后复验**：方法能捕捉用户异常且预期有独立来源；保存真实修复前后证据，配置／输入变化解释可比性，不能删断言或降预期换通过。
- **V-130 无法复现与偶发问题**：保留实际尝试、来源、触发条件、次数及失败数；缺 red 不补造，一次未复现不证明根除；调查缺权限不擅加生产探针或持久测试。
- **V-131 整包真实安装**：两个宿主安装包含八 Skill、shared、runtime 和模板的同一版本包后可完成最小闭环；缺 Python／资源或版本不匹配准确诊断，不自动装依赖，不以源码目录能运行冒充安装通过。
- **V-132 安装与接入分离**：包缓存、项目启用、项目资料分别定位；安装／doctor 不建库或批准知识，重复渠道不重复触发；宿主不支持项目范围时明确限制，不假报满足。
- **V-133 更新与在途执行**：运行版本固定或安全结束后切换；旧 Skill／新内核混用拒绝；包更新不隐式迁移 schema、不扩张授权、不重放请求；兼容后继沿有效范围续接。阶段升级若需改结构，具体迁移与恢复未验收不得宣称原地升级，不清除真实试用数据。
- **V-134 卸载重装与降级**：禁用／卸载保留项目数据、保护索引和未决效果；重装复用身份；不兼容降级拒绝写，代码回退不还原项目库或业务数据；清理数据另需明确请求。
- **V-135 领域资料按需复用**：映射既有术语／ADR，不重复建权威；只有有内容和实际取舍才建资料，正式内容仍经具体确认，不因术语讨论自动落正式规则。
- **V-136 经验转检查**：机械问题优先检查已有 lint／测试是否缺失或失效，再提小型改进；learn 不自行改 CI／hook／源码，普通授权修改验证后记录实际效果。
- **V-137 安装位置独立**：在当前实际执行环境中，移除原始下载副本、改变包缓存位置、使用空格／中文路径后资源仍正确定位；不引用临时克隆或包外兄弟资源，不把散装 Skill 安装误报整包成功。2026-10-31 用户明确只要求当前环境可执行，原 Windows 专项分支退出当前验收范围，历史未测记录不改为通过。

- **V-138 插件工程交付**：当前仓库根直接承载插件工程；源码、共享内核、开发测试工具、维护入口和设计资料可定位，工程规范只维护一份；目标项目配置／历史／证据与插件源码、发行内容分开。目录和文档按切片需要建立，不以空目录或模板存在冒充实现。
- **V-139 用户文档可操作性**：按对应发行版本的根 README 和指南，在两个宿主完成已开放能力的安装、首次接入及代表任务；实际命令、确认点、预期结果和资料位置一致；能力限制、模拟示例和已验收示例清楚，指南本地链接有效，读者无需先读内部设计。
- **V-140 发行内容与版本一致**：交付包包含八 Skill、单份 shared／runtime、所需模板、清单、许可证／必要来源声明及运行时引用的全部资料；用户指南随包提供或可定位至对应固定版本，包内执行不依赖在线文档或源码仓库。版本、清单、CHANGELOG 和受检包摘要一致；设计基线、插件发行版本、schema／内核协议分别标识，源码测试／历史快照及用户数据不误入运行包；缺资源、混合版本或文档不符则不通过。

## 用户体验、学习与宿主演练

每个宿主 M1 必须实测最小纵向流程：发现 Skill／资源 → 增量接入 → 短方案 → 授权实施 → 相关检查 → 正常封存本轮进度 → 新会话恢复。学习使用真实产生的候选及来源，再检索、核实、采用或拒绝并保存反馈，不仅引用预置资料。尚未实现的复杂能力如实 unavailable，不用假记录贯通流程。

固定小案例集包含：重复同类异常、已知业务口径的新功能、过时经验、反例、手工修改、多任务冲突及缺测试环境。首次与再次执行对照记录：

- 用户需要重复补充的已确认信息及原因；
- 命中条目、实际采用和影响；
- 错误或过时建议是否被识别；
- 重复失败是否被避免，未改善时保留原因；
- 用户确认次数、必须阅读内容和恢复步骤。

不以引用量或条目数宣称“变聪明”，不在没有基线时承诺百分比改善。候选与正式规则混用、未授权修改、失效证据记通过属于不允许出现的行为；性能和检索阈值先测量再制定，不为指标建设后台。

### 切片执行与阶段收口

每个 IMP 的实施记录包含以下内容，复用既有记录文件，不再另建一套计划或业务 Task：

1. **开工核对**：前置切片的适用门槛、当前代码／包版本、原有试用资料及本切片范围；列出必要接口与持久结构变化。需要定向迁移时先明确保护、迁移和恢复判据。
2. **完整路径**：按起始条件 → 用户请求／具体授权 → 实际操作 → 可观察成果拆内部步骤；工程入口、用户指南与行为实现一起交付，未开放分支明确 unavailable。

保留通用成果／验收／分析，不新建数据平台；正式环境修改按 D-022，部署与发布部分退出。

### D-017：单项目积累与实现验证终点（2026-10-31）

用户明确四类工作都会使用，核心是减少重复背景、积累经验，完成实现与测试，无需部署；随后明确只需单个项目持续积累。由此移除发布及个人库。

### D-018：按任务复杂度推进、按项目需求梳理（2026-10-31）

简单任务先短方案；复杂任务生成 spec 和任务清单逐项实现，借鉴 Matt。梳理轻量／深入／全局由项目和需求共同决定，不固定首次全量整理。

### D-019：未明确修改先调查与方案（2026-10-31）

用户明确“只要没有明确说要执行修改，都需要先调查给出方案再执行修复动作”。简单任务直接推进仅适用于已有明确修改授权；复杂任务整体方案确认后执行，原授权范围内不重复确认。

### D-020：正式知识集中确认、候选可作线索（2026-10-31）

正式知识修改先提示和方案，集中确认；影响当前方向的冲突及时提出。未确认经验可供调查，不能作为正式规则。执行事实自动留档，知识未批准不掩盖实现结果。

### D-021：允许外部编辑与多任务并存（2026-10-31）

用户明确项目不应受工具约束；允许手工／其他工具修改，工具检查现场并接纳事实。多个任务和会话分别保存进度，共享项目知识，重叠与依赖时协调。

### D-022：正式环境修改需具体授权（2026-10-31）

默认分析与指定测试环境验证；经明确授权可执行正式环境数据修改。范围、脚本、目标和恢复安排必须具体；结果未知先核实，不能自动重复执行。

### D-023：按影响范围验证（2026-10-31）

相关验收与必要回归，复杂或广泛影响扩大范围，缺必要测试在任务内补充；缺环境说明受阻，不冒充通过。

### D-024：采纳整体修订并授权重构设计（2026-10-31）

用户要求按已审阅建议整体重构设计。落实八个 Skill、十四动作、成果封存与知识应用解耦、前移宿主及学习验证；基线 0.6.0。此次授权用于文档／图册修订，不进入插件编码。

### D-025：采纳 Matt 对比并修订实施计划

2026-10-31，用户认可完整小流程拆分、代码审查、可重复排错判据及整包安装／升级约定，要求直接修订设计和分阶段实施计划，保持现有职责与授权，暂不编码。既有八个 Skill、十四动作、单项目知识与无部署边界继续有效；采用工程方法不等于启用 Matt 的自动多代理、提交或 worktree 工作流。

### D-026：插件工程结构与用户文档随功能交付

2026-10-31，用户认可参考 Matt 仓库的工程组织建议，要求完善实施计划。当前仓库作为未来插件工程根，保留八个 Skill 与共享运行时；根 README 提供安装和快速上手，用户／开发说明随切片验收，工程源码与目标项目资料分开。本次仅修改设计与实施计划，尚未授权插件编码、安装或发布。

## 工程方案与理由

- **P-001**：继续 Python 3.11+ 标准库与 TOML；受控写入子集和往返校验，避免承诺通用无损编辑器。
- **P-002**：任务完整定义／状态归 SQLite，spec 引用任务概要；简单方案允许内联 artifact 快照，避免强制文件。
- **P-003**：Change 为修改单位，分析用 run 链；原“发布聚合变更”退出，不新建总任务领域实体。
- **P-004**：版本校验和短事务保留，原仅顺序写入边界更新为资源范围协调；影响判断不可靠时保守核查，见 runtime。
- **P-005**：操作清单与一致备份保留；配置化发布协议退出，通用外部操作按 P-014。减少完成点全量备份并补容量边界。
- **P-006**：项目级安装、资料映射与最小导航保留；宿主发现前移实测。
- **P-007**：薄入口、状态建议和有证据的项目经验保留；候选与正式规则加载分开。
- **P-008**：知识晋升简化为项目内提案与具体批准；移除个人库，反例与效果反馈优先。
- **P-009**：多 Skill 共享内核与 run 承接保留；无独立交接／回执协议。
- **P-010**：原 0.5.1 双路径审查的分析、恢复、来源保障保留；与本轮范围冲突部分由 D-017—D-024 替代。
- **P-011**：原入口／配置／续接审查保障保留；发布父阶段配置例外取消，init 调整独立 run。
- **P-012**：通用成果与按需模板保留，数据字段只在相关时必须；不建设平台适配。
- **P-013**：事实、正式知识、分析与导出职责保障保留；初次正式基线也走具体批准。
- **P-014**：外部数据操作使用 operations 的效果结果与 resource_claims；本地登记和外部效果正交，不依赖 Release，避免重发未知结果。
- **P-015**：knowledge_proposals 统一项目内基线／规格／规则提案，替代 promotion_proposals 项目用途；集中展示不新增审批平台，批准与应用分开。
- **P-016**：实施改为 M1 最小闭环、M2 复杂任务与学习、M3 授权外部操作与维护。能力先实测，再按结果迭代。
- **P-017**：0.6.0 严格审核修订为 0.6.1。补齐必需知识成果闭环、正常轮次收尾、同定义修复、完成前核查、知识提案版本及恢复／实际派发边界；取消冗余 init profile，复用既有对象和控制清单，不增加 Skill、顶层动作或服务。具体发现与证据见 [本轮审核](archive/design-review-0.6.0.md)。
- **P-018**：0.6.2 将建设计划改为 IMP-001—IMP-014 完整小流程，基础封存与整包安装前移 M1；审查归 verify、修复归 apply、诊断证据复用现有对象；宿主管包、init 接项目，更新不隐式迁移或改授权。V-126—V-137 与案例 S—V 覆盖采用边界，见 [修订与来源](archive/revision-0.6.2.md)。

- **P-019**：按 D-026 将工程目录、安装／使用／开发文档与发行内容核查分配至既有 IMP-001—IMP-014，不新增切片或依赖。保留设计基线 0.6.2；插件发行版本独立标识，宿主清单、源码与运行资料按同一交付版本校验，文档可操作性以真实包演练证明。

具体字段及算法归 [runtime](runtime.md)，此处只保存选择理由。未实现的工程可行性不写成已验证事实。
