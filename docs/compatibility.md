# 版本与兼容

Evolve 0.4.0 使用 protocol 18、SQLite schema 4 和配置版本 1。插件发行版本与项目档案协议分别标识。

## 运行前提

- Python 3.11+；运行时使用标准库。
- Codex 或 Claude Code 的插件功能；安装步骤见[安装指南](installation.md)。
- 数据派发与离线换库需要可观察的 POSIX 进程组及 `lsof`。缺少能力时，对应操作会受阻并保留现场。

普通源码开发、调查与 SQL 检查遵循项目自己的环境配置。数据写入支持可固定的同步 Python／SQLite 机制；远程 provider、动态／后台机制需要另外具备相应适配能力，当前没有通用连接器。

## 项目档案支持路径

| 来源 | 当前处理 |
|---|---|
| 未接入项目 | 只读查看状态，明确接入后建立身份、配置和历史 |
| schema 4／protocol 18 | 按当前任务、现场与授权处理新请求 |
| 健康的 schema 4／protocol 14、15、16 或 17 | 先由匹配的旧完整包处理未完成操作，再明确生成和应用升级方案，升级至 18 |
| protocol 18 的完整备份 | 呈现准确恢复方案，保护当前现场，安装新工作 epoch |
| 其他旧版或未知更高版本 | 保留资料，使用匹配的完整包诊断，当前包不会自动降级或清库 |

14／15 升级后，缺少外部保护索引的状态保持 `unverified`，不能据此开始新的数据写入。目标及来源缺少足够核实能力时继续受阻。

## 更新与恢复的边界

先完成或核实原操作，保留旧完整包，再安装新包。正在执行的请求绑定原版本、摘要和身份；更换包或恢复档案后，不能用当前绑定重放旧请求。

安装插件与接入项目不会隐式升级档案。档案恢复保持当前业务源码、业务数据库和外部效果，需要另行核实实际结果。具体集合、容量、进程排空和冲突处理见[维护协议](../shared/recovery.md)。

## 0.3.0 兼容补充

保持 protocol 17／schema 4；0.2.0 健康档案可直接读取，不需要重复接入或迁移。新增 maintain.repair 为显式维护动作，支持完整当前保护下缺失检查、无外部执行历史时缺失发送索引，以及有封存接入依据的缺失初始化日志。现存错误身份、未决运行或未知执行保持受阻。

新增 workflow、readiness、activation 和候选包检查为回执／查询信息，原字段和历史含义保留。--session-package-digest 是宿主会话提供的观察，匹配仅证明该摘要与执行包一致；宿主实际启用另行观察。

## 0.4.0 兼容补充

protocol 18 固定检查环境及修改前检查，并使简短方案的保行为要求参与完成核验；旧写入器不能忽略这些约束。schema 保持 4；健康 protocol 17 档案沿显式维护升级，普通安装和接入保持原档案。历史执行、知识正文和旧失败保留，当前验收重新核对现场与环境。
