# 版本、兼容与限制

本地工程版本0.1.0，设计基线0.6.2，内核protocol16，SQLite schema4，配置版本1。插件版本、协议和schema分别表示；安装同名插件不等于项目已接入或已批准业务操作。

## 当前支持路径

| 来源 | 当前行为 |
|---|---|
| 未接入项目 | 先只读status；明确init后建立新身份、配置和档案 |
| 当前schema4／protocol16 | 新请求核对实际项目、当前任务和授权；原执行按原完整版本／摘要与请求保留，不在换包后重绑重放 |
| 健康schema4／protocol14或15 | 先由对应完整旧包处理未完运行／文件日志和检查，再明确maintain.upgrade计划与apply，定向升级到16；普通init不迁移 |
| 协议16的准确完整备份 | 明确maintain.restore，保护当前现场、排空旧实例、安装新epoch；不恢复业务数据 |
| 其他旧版本、未知更高schema／protocol | 保留资料，使用适用完整兼容包或只读诊断；不自动降级、清库或手改版本号 |

14／15→16是本轮实际提供的定向路径，不承诺任意未来迁移。步骤及容量、保护和冲突门禁由[完整档案维护](../shared/recovery.md)维护。旧14／15项目没有外部保护索引时升级结果保持unverified，不能因此派发新数据写入；没有足够目标／已知操作核实能力时继续受阻，不提供手改索引解锁入口。

包更新前完成原操作，保存旧完整包。兼容更新使用新请求消费适用的保存事实；已记录请求不能换当前epoch、定义或摘要重试。旧epoch不会因为恢复而获得新写权限，历史passed／archived与当前适用性分别显示。

## 已验证环境与边界

工程使用Python3.11+标准库。当前验收环境为macOS；用户已明确只要求当前环境可执行，其他平台不作为独立门槛，历史未测项不改称通过。外部派发及离线进程排空需要当前可观察的POSIX进程组／lsof；能力缺失时明确拒绝对应操作，不自动安装环境。

两个宿主完整安装、资源发现和项目范围启用分别验证；实际模型执行另存证据。先前高级组合场景按用户Codex优先范围推进，Claude因429暂停的原始事实保留，不能用共用内核测试或安装发现代替其原生模型证据。

外部数据执行只支持可固定的有限同步Python／SQLite项目机制；不提供通用连接器。正式目标、远程provider、动态／后台／延迟工作和业务项目移动后的隐式目标重绑没有通过证据。候选与目标实质变化需新准确批准，unknown不换ID重发；详见[数据操作](../shared/external-work.md)。

## 历史和后续

开发alpha的失败、协议变更和修复记录保留在CHANGELOG及源码验收资料。失败候选alpha.24不作为通过基线；alpha.25完成当前Codex范围M3数据门槛。本版本最终联合验收使用同一具体包和实际摘要判断，不从版本名称推断通过。

公开许可／市场上架、特定正式provider接入和检索阈值的长期测量是后续选择，不作为已完成事实。当前仅本地／私有交付，不自动提交、发布或部署。
